# Состояние тестового сьюта

Этот файл — указатель, не отчёт. Числа живут там, где они получены: в дневных
трейслогах `changelogs/CHANGE_TRACE_LOG_YYYY-MM-DD.md` и в `CHANGELOG.md` при релизе.
Здесь они не переписываются, потому что переписанное число отстаёт от прогона в тот же
день, когда его переписали (предыдущая редакция этого файла сообщала «670 passed,
Production Ready» от 2025-10-28 при 3258 passed на 2026-09-04).

**Статус проекта — Beta.** Основной путь (MACD, `global` свинги) держится инвариантами.
Развёрнутый разбор готовности — `devref/architecture/READINESS_2026-09-10.md` (снимок на
`3b8b80a`: что держится и чем измерено, что отсутствует по решению владельца, что тонко на
самом деле, и §7 — темы, названные, но не проработанные). Предыдущий снимок —
`PRODUCTION_READINESS_2026-09-07.md`.

*Обновлено 2026-09-12.* Открытых записей в реестре не осталось: G70 (пустой контекст
свингов молчал о причине), G71 (рычаги билдера сведены в таблицу «включено ≠ выключено»)
и G72 (у входа анализа не было контракта) закрыты; **G6** остаётся 🟢 by-design. Из
двенадцати критериев готовности (§15 аудита) пункт 12 закрыт на флагманском пути (G71) и
с 2026-09-12 ещё на трёх — визуализация зон, статистика, загрузка и валидация данных
(G75–G79, по таблице рычагов «включено ≠ выключено»); сплошной проверки по всему
публичному API по-прежнему нет и не планируется; пункт 10
(«STATUS, реестр и changelog согласованы») с 2026-09-12 сверяется сторожем —
`tests/unit/test_status_claims_match_the_registry.py`: номер, названный документом, обязан
быть в реестре, а живой документ обязан согласовываться с реестром в том, открыт он или
закрыт. Сверка перестала быть целиком ручной, но сторож проверяет **механические**
утверждения, а не смысл: фразу «инвариантов нет» рядом с инструкцией, как их запускать, он
по-прежнему не увидит. Из этапа 5 аудита
последний пункт — property-based инварианты — закрыт в тот же день
(`devref/architecture/property_based_invariants_backlog_2026-09.md`, §6;
`tests/unit/test_invariants_hold_on_generated_data.py`).

*Как этот файл протухал — дважды за один день, для памяти.* Редакция от 2026-09-07
называла открытыми записи G53–G59, закрытые тремя релизами раньше; следующая, в тот же
день, назвала открытым G26 — его закрыли несколькими часами позже. Файл, заведённый ровно
затем, чтобы числа не протухали, протухал в статусе. Отсюда правило: **что открыто —
знает `devref/gaps/gap_inventory_2026-07.md`, и только он**; здесь стоит дата последней
сверки, а не второй список.

Почему статус всё-таки Beta, а не выше: пункт 12 закрыт только на флагманском пути,
API ломается без окон устаревания, и **нет CI** — двуплечевой прогон перед релизом запускается вручную. CI не
заводится **по решению владельца от 2026-09-07**, а не по недосмотру: внешних
контрибьюторов нет, а релизный гейт строже типичного CI. Принятая цена — дрейф
зависимостей снаружи виден только на релизе (так нашёлся G50). Пересмотр — когда появятся
внешние потребители помимо лабы. P0-дыры аудита закрыты, и то, что оставалось до доверенных
чисел на флагмане (G70, G71, G72), закрыто 2026-09-07/09 — новый каталог находок для
этого не понадобился.

## Как гонять

```bash
python -m pytest -q                 # полный сьют, ~7,5 минут
python -m pytest -q -m "not slow"   # без медленных
python -m pytest -q -m slow         # только широкий поиск по инвариантам
```

Часть сьюта генерирует входы сама (`tests/unit/test_invariants_hold_on_generated_data.py`,
`hypothesis` из `dev`-extra): по умолчанию 12 примеров на свойство и фиксированный набор
(красное воспроизводится), широкий поиск на 120 примеров — под меткой `slow` и относится
к релизному гейту, а не к обычному прогону.

Пропусков без условия в сьюте нет; условные (`@pytest.mark.skipif`) называют условие.
Релизный гейт — сьют из **чистого клона** с зависимостями, как они разрешаются сегодня,
плюс контрольное плечо на нижней поддерживаемой версии pandas (G50).
