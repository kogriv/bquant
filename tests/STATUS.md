# Состояние тестового сьюта

Этот файл — указатель, не отчёт. Числа живут там, где они получены: в дневных
трейслогах `changelogs/CHANGE_TRACE_LOG_YYYY-MM-DD.md` и в `CHANGELOG.md` при релизе.
Здесь они не переписываются, потому что переписанное число отстаёт от прогона в тот же
день, когда его переписали (предыдущая редакция этого файла сообщала «670 passed,
Production Ready» от 2025-10-28 при 3258 passed на 2026-09-04).

**Статус проекта — Beta.** Основной путь (MACD, `global` свинги) держится инвариантами.

*Поправка 2026-09-07.* Прежняя редакция этой строки называла **открытыми** записи G53–G59 —
те самые пути, которые «могут молча вернуть результат других данных или другого алгоритма».
Они закрыты 4–5 сентября и вышли в 0.0.12–0.0.13; файл, заведённый ровно чтобы числа не
протухали, протух в другом месте — в статусе. Сейчас в реестре
(`devref/gaps/gap_inventory_2026-07.md`) открыты **G26** (свойства типа зоны теряются на
границе со списком словарей: самостоятельный путь `run_all_hypothesis_tests(zones_features)`
даёт 5 тестов из 7, через пайплайн — все 7) и **G6** (`custom` ≠ pandas-ta, by-design), плюс
остатки **G40** и **G47**. Аудит `devref/architecture/PROJECT_QUALITY_AUDIT_2026-09-04.md`
исполнен целиком, кроме этапа 5 («усилить доказательства»); его статус исполнения — §0 там же.

Почему статус всё-таки Beta, а не выше: из двенадцати критериев готовности (§15 аудита) не
выполнен пункт 12 целиком (сплошной проверки «каждый публичный параметр различим тестом»
нет) и **нет CI** — двуплечевой прогон перед релизом запускается вручную.

## Как гонять

```bash
python -m pytest -q                 # полный сьют, ~7 минут
python -m pytest -q -m "not slow"   # без медленных
```

Пропусков без условия в сьюте нет; условные (`@pytest.mark.skipif`) называют условие.
Релизный гейт — сьют из **чистого клона** с зависимостями, как они разрешаются сегодня,
плюс контрольное плечо на нижней поддерживаемой версии pandas (G50).
