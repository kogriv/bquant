[included] [Fixed] bquant/analysis/zones/strategies/swing/find_peaks.py — G14: исходный диагноз («+2 бара лаг scipy prominence-base») **опровергнут прогоном**. Настоящая причина — порядок фильтров внутри scipy: `find_peaks` применяет `distance` **до** `prominence`, жадно по убыванию высоты и по **всему** множеству сырых локальных максимумов. Экстремум, подавленный более высоким соседом в пределах `distance`, **оживает**, когда сосед сам снимается ещё более высоким справа (замер: пик 178 подавлен 180, возвращается на баре 183 с появлением 182). Новый `_distance_settled_bar` — BFS по транзитивной цепочке подавления (все локальные максимумы в пределах `distance`, не ниже текущего; ничьи считаются подавляющими — консервативно), `settled = max(p + distance)` по членам цепочки. `_confirmation_index` переписан на унифицированную серию детекции (highs / −lows), prominence-сторона обоснована монотонностью: усечение только укорачивает интервал правой базы
