# G26 — Дока не передаёт словарь типов зон, хотя параметр для него есть

**Заведён:** 2026-08-28 · **Статус:** 🟢 решено осознанно — правка нужна **только в доке**,
код менять не требуется. Фактическая починка идёт в G25 (пп. 8–9).
**Как найден:** при разборе `KeyError: 'p_value'` в примере из `quick_start.md` (G25 §2, п. 8).

---

## 1. Поправка к первой редакции этой записи

Заведена она была с диагнозом «словарь типов зон **теряется** на границе со списком
словарей, нужен новый параметр». **Диагноз неверен, и вот чем он опровергнут:**

```
run_all_tests:            (self, zones_features, vocabulary: Optional[ZoneVocabulary] = None)
run_all_hypothesis_tests: (zones_features, alpha=0.05, vocabulary: Optional[ZoneVocabulary] = None)
```

Параметр **уже есть** у обоих. Более того, он **уже документирован** —
`docs/api/analysis/statistical.md` показывает ровно правильный вызов:

```python
from bquant.analysis.zones.detection import resolve_vocabulary

vocabulary = resolve_vocabulary(result.zones)
tests = test_suite.run_all_tests(zones_features, vocabulary=vocabulary)
```

Замер на `tv_xauusd_1h`, MACD, 32 зоны:

| Вызов | Результат |
|---|---|
| `run_all_hypothesis_tests(zf)` | **5 из 7** тестов дают `p_value` |
| `run_all_hypothesis_tests(zf, vocabulary=voc)` | **7 из 7** |

Так что «возможность теряется» — неправда. Возможность на месте, ею просто не
пользуются две страницы доки из трёх.

## 2. Что происходит на самом деле

`ZoneFeatures.to_dict()` действительно отдаёт плоский словарь: остаётся **имя** типа
зоны (`'bull'`), не остаются его **свойства** (`polarity`, `counterpart` из `ZoneType`,
введённых в G20). Это by-design: словарь свойств закрыт и живёт отдельно от данных.
Поэтому вызов без `vocabulary` честно отказывается считать две направленные метрики:

```
contrast_asymmetry:   "No contrasting pair of zone types is available:
                       observed types ['bear','bull'], declared pairs []"
correlation_drawdown: "No zone type declares a polarity ... observed types: ['bear','bull']"
```

Отказ называет и причину, и способ её снять. Это прямой результат G20: до него на этом
месте возвращался не пустой результат, а *ложный* — нулевая матрица со `states:
['bull','bear']` и стационарным `[1.0, 0.0]`.

## 3. Дефект

Он в доке, и он ровно того же рода, что весь G25: **две страницы показывают вызов,
который тише полного на два теста, и не говорят об этом**, при том что третья страница
показывает правильный вызов и объясняет, зачем он нужен.

| Где | Что |
|---|---|
| `docs/user_guide/quick_start.md` | вызывает без `vocabulary` → `KeyError: 'p_value'` |
| `docs/api/data/samples.md` | то же |
| `docs/api/analysis/statistical.md` | **правильно**: передаёт `vocabulary`, объясняет отказ |

## 4. Решение

Правится в доке, вместе с остальными пунктами G25: два примера приводятся к тому виду,
который уже описан в `statistical.md`. Кода это не касается — менять сигнатуру,
у которой нужный параметр уже есть, было бы починкой несуществующего.

**Урок для протокола:** прежде чем объявлять «возможности нет», проверить сигнатуру.
Отказ, который *объясняет*, чего ему не хватает, обычно и означает, что недостающее
можно передать.
