# G33 — Восемь модулей объявляли свою версию, и она разошлась с пакетом

**Заведён:** 2026-08-29. **Статус:** ✅ закрыт в тот же день.
**Нашли:** попыткой честно описать `get_visualization_info()` из списка G31.

---

## 1. Как нашли

Чтобы записать в доку, что возвращает функция, её надо запустить. Запустили:

```
get_visualization_info()['version'] = '0.0.0'      при пакете 0.0.9
```

## 2. Замер

Восемь подпакетов объявляли собственный `__version__` литералом:

| Модуль | Было |
|---|---|
| `bquant.analysis` | `"0.0.0"` |
| `bquant.analysis.statistical` | `"0.0.0"` |
| `bquant.analysis.zones` | `"0.0.0"` |
| `bquant.visualization` | `"0.0.0"` |
| `bquant.analysis.candlestick` | `"0.1.0-stub"` |
| `bquant.analysis.chart` | `"0.1.0-stub"` |
| `bquant.analysis.technical` | `"0.1.0-stub"` |
| `bquant.analysis.timeseries` | `"0.1.0-stub"` |

## 3. Почему это не косметика

Число **выходило наружу**:

- `get_visualization_info()` отдавал `version: "0.0.0"` как факт о пакете, и
  `print_visualization_status()` печатал `BQuant Visualization Module v0.0.0`;
- четыре заглушки клали свою версию в `metadata` результата анализа.

Форма — та же, что в G8 и G32: **второй литерал**, обязанный совпадать с первым, и
никем не сверяемый. Первый двигается на каждом релизе, второй стоит. Причём здесь
разъезд гарантирован самим процессом: релизная процедура правит версию в
`pyproject.toml` и `bquant/__init__.py`, и про эти восемь мест не знает.

Показательно, что правильный способ в репозитории уже был — `analysis/zones/cache.py`
делает `from bquant import __version__`. Один модуль знал, восемь не знали.

## 4. Что сделано

- Все восемь берут версию у пакета: `from bquant import __version__`. Циклического
  импорта нет — `bquant/__init__.py` присваивает `__version__` до любых импортов
  подпакетов.
- `"0.1.0-stub"` убран без потери смысла: заглушки и так кладут в метаданные
  `implementation_status: 'stub'` — признак заглушки был там, где ему место, а в номере
  версии он дублировался.
- `tests/unit/test_the_package_has_one_version.py` — пин: любой модуль, объявляющий
  `__version__`, обязан объявлять ту же, что у пакета. Обход параметризован, так что
  новый модуль со своим литералом покраснеет сразу.

## 5. Проверка

```
расхождений по версии: 0
get_visualization_info()['version'] = 0.0.9
print_visualization_status() → BQuant Visualization Module v0.0.9
```
