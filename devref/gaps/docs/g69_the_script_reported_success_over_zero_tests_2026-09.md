# G69 — Скрипт печатал «Successful Tests: 2» на семи тестах, ни один из которых не выполнился

**Заведён и закрыт:** 2026-09-07.
**Как найден:** попутно при закрытии G26 — сверял, кого в репозитории затронет отказ
теста последовательностей без словаря, и увидел, что число выполненных тестов у
`scripts/analysis/run_hypothesis_tests.py` не меняется ни до правки, ни после. Число,
которое не реагирует на правку, которая обязана его менять, — это не число.

---

## 1. Что печаталось и что происходило

```
==================================================
BQuant Hypothesis Testing Results
==================================================
Symbol: XAUUSD
Successful Tests: 2
Significant Results: 0
```

Код возврата — 0. На самом деле (замер на `tv_xauusd_1h`, 30 зон,
`--sample-data --all-tests`):

| | |
|---|---|
| тестов объявлено | 7 |
| **тестов выполнилось** | **0** |
| ошибка каждого | `Mixing dicts with non-Series may lead to ambiguous ordering` |
| напечатано | `Successful Tests: 2` |

## 2. Механизм — две ошибки, каждая безобидная по отдельности

**Первая.** В `run_all_hypothesis_tests` уезжал **конверт**, а не список признаков:

```python
zones_info = {'zones_features': [...], 'zones': [...], 'statistics': ..., 'hypothesis_tests': ...}
test_results = run_all_hypothesis_tests(zones_info, alpha=alpha)   # ← сюда нужен список
```

Функция ждёт `List[Dict]`, получает `Dict`, и каждый тест падает внутри pandas.

**Вторая.** Счётчик спрашивал не «посчитался ли тест», а «нет ли у записи ключа
`error`» — и спрашивал это у **верхнего уровня ответа**:

```python
for test_name, result in test_results.items():      # ключи: 'tests', 'summary'
    if isinstance(result, dict) and 'error' not in result:
        successful_tests += 1                        # → 2
```

Ответ `run_all_hypothesis_tests` — конверт `{'tests': {...}, 'summary': {...}}`. Обе
записи — словари без ключа `error`, отсюда двойка. Внутри `summary` при этом честно
стояло `tests_executed: 0, tests_failed: 7` — сводка пакета знала правду, скрипт её не
читал.

**Следствие, которое хуже обоих:** `_generate_recommendations` шёл по тому же конверту,
получал «два валидных теста, значимых ноль» и печатал вывод о рынке —
«Limited statistical evidence in MACD patterns / Consider additional indicators for
trading decisions» — выведенный из нуля посчитанных тестов.

## 3. Что нашлось рядом, пока чинилось

* `_summarize_zones` считала `z.get('type') == 'Bull'`. Поле называется `zone_type`, а
  значения — `bull`/`bear` строчными: обе группы всегда были нулевыми, `bull_ratio` —
  `0.0` на любых данных. Заодно это был хардкод `bull`/`bear`, снятый в G20.
* Каталог тестов скрипта объявлял собственное **третье** имя `patterns`, которого пакет
  не знает (`run_single_hypothesis_test` принимает `sequence`): выбранный тест молча не
  запускался. Всего имён было два набора — короткие у одиночного вызова
  (`duration`, `sequence`) и ключи сводки у полного (`zone_duration`,
  `sequence_patterns`), — и отчёт печатал то заголовок, то ключ, смотря какой веткой шли.
* Ветка `--tests` клала в результаты **объект** `HypothesisTestResult`, а счётчик
  проверял `isinstance(result, dict)` — то есть одиночные тесты не считались вовсе.
* `--verbose` падал: `f"{p_value:.6f if p_value else 'N/A'}"` — спецификатор формата,
  которого нет; при `p_value = None` это `unsupported format string passed to
  NoneType.__format__`, код возврата 1.
* `--output ... --output-format json` падал **после** починки счёта: `significant` у
  результата теста — `np.bool_`, и запись давала `Object of type bool is not JSON
  serializable`. Пока ни один тест не считался, в отчёт ехали одни строки ошибок, и
  выгрузка проходила — то есть её тоже никто ни разу не проверил на настоящем
  результате. Заодно `_serialize_for_json` переписывала результаты в словарь с полями
  `test_name`, `is_significant`, `interpretation`, которых у `HypothesisTestResult` нет:
  получалось пять `None` на тест. Метод заменён обработчиком `default=` для скаляров
  numpy.

## 4. Почему сьют этого не видел

`tests/integration/test_scripts_integration.py::test_test_hypotheses_script` проверял,
что в выводе есть заголовок «hypothesis testing results», и **заранее прощал** ненулевой
код возврата:

```python
else:
    print(f"Hypothesis testing failed (may be expected): {result.stderr}")
    hypothesis_success = False
```

Тест, прощающий тот отказ, ради которого он написан, — не тест. Ни одна проверка не
спрашивала **число** посчитанных тестов, а именно оно и было сломано.

## 5. Правка

`scripts/analysis/run_hypothesis_tests.py`:

1. В тесты уезжает `zones_info['zones_features']`, а словарь типов зон резолвится из
   зон (`resolve_vocabulary`) и передаётся — иначе три направленных теста откажутся
   считать (G26).
2. Счётчик считает **тест**: выполненным считается тот, у которого есть числовой
   `p_value`; причины невыполнения собираются в `testing_summary['failed_reasons']`.
3. **Ноль выполненных — отказ** (`ValueError` с перечнем причин), а не отчёт с
   рекомендациями. Код возврата ненулевой.
4. Ветка `--tests` кладёт `result.to_dict()`: одна форма для обеих веток.
5. Соответствие «имя для `--tests` ↔ ключ сводки ↔ заголовок» объявлено **одной
   таблицей** (`tests_catalogue`); `patterns` заменён на настоящее `sequence`, добавлены
   `correlation_drawdown` и `stationarity` — итого семь, как в пакете.
6. `_summarize_zones` считает по `zone_type` и по **наблюдаемым** типам
   (`zones_by_type`), без `bull`/`bear` в коде.
7. Починен спецификатор формата в текстовом отчёте.

Замер после правки (`--sample-data --all-tests`): **7 выполнено, 4 значимых**, `--verbose`
проходит, коды возврата 0 / 1 (неизвестный тест) как положено.

## 6. Сторож

`tests/integration/test_the_hypothesis_script_reports_what_ran.py` — шесть проверок:
семь объявленных тестов дают семь посчитанных и `0 < значимых < 7`; ветка `--tests`
считается так же; отчёт по нулю выполненных тестов отвергается с названными причинами;
сводка зон считает по объявленному типу; JSON-выгрузка читается обратно и несёт `float`
и `bool`; напечатанное число совпадает с посчитанным (подпроцессом).

Мутации: вернуть передачу конверта — 2 красных; вернуть счётчик «нет ключа error» —
1 красный; вернуть ключ `type` в сводке зон — 1 красный; убрать обработчик numpy из
`json.dump` — 1 красный.

Прежний интеграционный тест лишён прощения «may be expected»: обе ветки теперь обязаны
завершиться кодом 0.

## 7. Урок

Дефект держался на том, что **число выглядело правдоподобно**. «2» не похоже на
поломку — похоже на «часть тестов не подошла к данным». Ноль или семёрка бросились бы в
глаза; двойка не бросилась никому, включая меня, пока я не сравнил её до и после правки,
которая обязана была её изменить.

Отсюда правило, применимое шире: **у любого счётчика в отчёте должен быть замер, который
его двигает.** Если правка меняет предмет счёта, а число стоит на месте — сломано число,
а не правка.
