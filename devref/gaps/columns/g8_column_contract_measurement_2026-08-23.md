## 1. Корень

Имя колонки тащит на себе **две несвязанные вещи сразу**:

- **идентичность** — какой экземпляр индикатора это посчитал (MACD(12,26,9) или MACD(5,35,5));
- **роль** — что этот ряд означает (линия, сигнал, гистограмма).

`macd_hist` = «MACD с какими-то параметрами» + «гистограмма», слипшиеся в один литерал.
Отображением между ними никто не владеет: **каждый производитель выдумывает строку,
каждый потребитель её угадывает**. Как только данные попадают в `DataFrame`, знание
«какая колонка что значит» теряется — остаются голые строки.

Отсюда три наблюдаемых следствия.

---

## 2. D1 — три соглашения об именах

Замер по всем пяти custom-индикаторам, что есть в пакете:

| Индикатор | Колонки | Соглашение | Параметры в имени |
|---|---|---|---|
| `sma`, `ema`, `rsi` | `sma_20`, `ema_20`, `rsi_14` | имя + период | ✅ есть |
| `macd` | `macd`, `macd_signal`, `macd_hist` | имя без периода | ❌ **потеряны** |
| `bbands` | `bb_upper`, `bb_middle`, `bb_lower`, `bb_width`, `bb_percent` | **сокращённое** имя (`bb`, а не `bbands`), без периода | ❌ **потеряны** |

Три индикатора — три правила. Пользователь не может вывести имя колонки из имени
индикатора и обязан лезть в исходник.

**Практическое следствие — потеря параметров.** Два экземпляра одного индикатора с
разными настройками претендуют на одно имя:

```
rsi     ['rsi_14']  vs ['rsi_21']                          -> различны
macd    ['macd','macd_signal','macd_hist'] vs то же самое  -> СТОЛКНОВЕНИЕ
bbands  ['bb_upper',...] vs то же самое                    -> СТОЛКНОВЕНИЕ
```

То есть непоследовательность не косметическая: там, где период в имени есть, версии
сосуществуют; где его нет — молча затирают друг друга.

## 3. D2 — тихое затирание при слиянии

`bquant/analysis/zones/pipeline.py:294-295`:

```python
for col in result.data.columns:
    df_with_indicator[col] = result.data[col]
```

Безусловное присваивание. Проверок на занятость имени нет.

**Столкновение с колонками самих данных.** Встроенный сэмпл TradingView несёт
собственные `macd`, `signal`, `rsi`, `rsi_based_ma` — они пришли из выгрузки. Custom-MACD
пишет колонку `macd` и подменяет пользовательскую:

```
macd  OVERWRITES ['macd']  (max|Δ| = 5.8424)
```

Расхождение до 5.84 по ряду **на дефолтных параметрах**. На последнем баре числа
совпадают, что делает подмену особенно незаметной при беглой проверке — расходится
середина ряда, а не хвост.

Прочие индикаторы на этом сэмпле не сталкиваются, но это везение, а не гарантия:
`rsi` custom даёт `rsi_14`, а в данных лежит `rsi` — разошлись случайно.

**Столкновение с самим собой.** Два MACD в один кадр:

```
after macd(12, 26, 9): macd_hist[-1] = 1.4951
after macd(5, 35, 5):  macd_hist[-1] = 1.2791
surviving columns: ['macd', 'macd_signal', 'macd_hist']  -> первый экземпляр утрачен
```

Восстановить первый нельзя — он не переименован, он перезаписан.

## 4. D3 — библиотечные колонки подписаны неверными параметрами

Худший из трёх. `bquant/indicators/library/pandas_ta.py:409`:

```python
result_df.columns = output_columns
```

`output_columns` вычисляется **один раз при регистрации** индикатора
(`_determine_output_columns`, строки 245+) — на синтетических данных, с **дефолтными**
параметрами — и кэшируется в конфиге. Дальше подставляется при каждом расчёте,
затирая имена, которые вернула сама библиотека.

```
rsi_length_14   bquant=RSI_14   pandas_ta=RSI_14   [ok]           values_correct=True
rsi_length_21   bquant=RSI_14   pandas_ta=RSI_21   [MISLABELLED]  values_correct=True
rsi_length_50   bquant=RSI_14   pandas_ta=RSI_50   [MISLABELLED]  values_correct=True
```

Читать так: **значения посчитаны правильно** — с запрошенным `length`. Врёт только
подпись. В колонке с заголовком `RSI_14` лежит RSI-50.

Это качественно хуже D1. `macd_hist` о параметрах **умалчивает** — пользователь знает,
что не знает. `RSI_14` **утверждает** параметры, и утверждает ложно. Плюс всё то же
столкновение: `rsi(14)` и `rsi(50)` дают одно имя и затирают друг друга.

Отягчающее: pandas-ta именует правильно сама (`ta.rsi(close, length=50).name == 'RSI_50'`)
— мы уничтожаем корректную информацию, а не восполняем отсутствующую. И в документации
`indicator_col='RSI_14'` встречается 15 раз, то есть мы этому учим.

---

## 5. Незакреплённый контракт (предпосылка, не дефект)

Каждый индикатор объявляет колонки в `get_output_columns()` и **повторно строит те же
литералы** внутри `calculate()`. Ничто не проверяет, что они совпадают.

```
sma MATCH · ema MATCH · rsi MATCH · macd MATCH · bbands MATCH
```

Сегодня совпадают — но по дисциплине, а не по конструкции. Это надо запинить тестом
**до** рефакторинга, иначе не отличить «сломали при переезде» от «было сломано».

## 7. Почему «просто переименовать» — не решение

Канонические `macd_12_26_9_hist` устранили бы D1 и столкновения, но пользователь
по-прежнему обязан знать точную строку, чтобы написать `detect_zones(indicator_col=...)`.
Мы заменим одно угадывание другим, более длинным, сломав при этом всех.

Проблема не в том, что имена **некрасивые**, а в том, что **отображение «колонка → смысл»
нигде не живёт**. Пока его нет, любое имя остаётся угадываемым литералом.

Проектное решение — в `g8_column_contract_design_2026-08-23.md`.
