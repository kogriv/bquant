# G8 — контракт выходных колонок: проектное решение (2026-08-23)

**Статус:** проект, не реализовано. Согласован объём и порядок работ; код не тронут.
**Разбор дефектов:** `g8_column_contract_measurement_2026-08-23.md`
**Замер:** `devref/gaps/columns/g8/g8_measure.py`

---

## 1. Что решаем

Три дефекта с общим корнем (нумерация из разбора):

- **D1** — три соглашения об именах, параметры теряются, экземпляры сталкиваются;
- **D2** — тихое затирание при слиянии в кадр (`pipeline.py:294-295`);
- **D3** — библиотечные колонки подписаны параметрами регистрации, а не вызова.

Корень: имя колонки совмещает **идентичность** (какой экземпляр посчитал) и **роль**
(что ряд означает), а отображением между ними никто не владеет.

### Чего решение обязано достичь

1. Имя колонки **однозначно** определяется индикатором и его параметрами.
2. Потребитель может получить нужный ряд, **не зная строки** — по роли.
3. Слияние в кадр **не затирает молча** ничего.
4. Существующий пользовательский код **не ломается в момент выхода** правки.

### Чего решение сознательно НЕ делает

- Не меняет **значения** индикаторов — только имена и способ адресации.
- Не трогает `devref/` и `changelogs/` — это история (288 вхождений).
- Не унифицирует имена **входных** колонок OHLCV — это отдельный контракт
  (`bquant/data/schemas.py`), у него свои потребители.
- Не переводит на роли внешние библиотеки целиком — pandas-ta имеет собственное
  соглашение, и его надо **уважать**, а не подменять (см. §4.3).

## 2. Абстракция

### 2.1 Идентичность — `IndicatorId`

Детерминированный слаг из имени и **нормализованных** параметров.

```python
@dataclass(frozen=True)
class IndicatorId:
    source: str                    # 'custom' | 'preloaded' | 'pandas_ta' | 'talib'
    name: str                      # 'macd', 'rsi', 'bbands'
    params: Mapping[str, Any]      # {'fast_period': 12, ...}

    @property
    def slug(self) -> str:
        """'macd_12_26_9', 'rsi_14', 'bb_20_2.0' — стабильно и воспроизводимо."""
```

Нормализация — существенная часть, а не деталь. Требования:

- **порядок параметров фиксирован** объявлением индикатора, а не порядком в `**kwargs`,
  иначе `MACD(fast=12, slow=26)` и `MACD(slow=26, fast=12)` дадут разные слаги;
- **дефолты подставляются явно** — `rsi()` и `rsi(period=14)` обязаны совпасть;
- **числа канонизируются** — `2` и `2.0` не должны расходиться (у pandas-ta `BBL_5_2.0_2.0`
  показывает, во что это выливается);
- **служебные параметры исключаются** — те, что не влияют на значения.

Информация **уже есть** и просто не используется: `CustomIndicator.__init__` получает
`(name, parameters)` и кладёт их в `IndicatorConfig.parameters`.

### 2.2 Роль — `OutputRole`

Индикатор объявляет выходы ролями, а не строками:

| Индикатор | Роли |
|---|---|
| MACD | `line`, `signal`, `hist` |
| Bollinger | `upper`, `middle`, `lower`, `width`, `percent` |
| RSI, SMA, EMA | `value` |

Роль — это то, что нужно потребителю. Детектору нужна «гистограмма», а не строка
`macd_hist`. Роли — **замкнутый словарь** на уровне пакета, а не свободный текст:
иначе получим ту же проблему этажом выше.

### 2.3 Имя колонки

```
{slug}__{role}        macd_12_26_9__hist,  bb_20_2.0__upper
{slug}                rsi_14                (единственный выход с ролью 'value')
```

Двойное подчёркивание разделяет идентичность и роль однозначно — имена индикаторов и
параметры сами содержат одиночные `_`.

### 2.4 Схема-спутник — `ColumnSchema`

После слияния в `DataFrame` объекты исчезают, остаются строки. Значит отображение
обязано пережить слияние.

```python
@dataclass
class ColumnSchema:
    """(IndicatorId, role) -> фактическое имя колонки в кадре."""
    entries: Dict[Tuple[IndicatorId, str], str]

    def column(self, indicator: IndicatorId, role: str) -> str: ...
    def roles_of(self, column: str) -> Optional[Tuple[IndicatorId, str]]: ...
```

Куда крепится:

- `IndicatorResult` уже имеет `config` и `metadata` — добавляем поле `columns: Dict[role, str]`;
- пайплайн копит `ColumnSchema` по мере расчёта индикаторов;
- `ZoneAnalysisResult` получает поле `column_schema`, и тогда визуализатор, которому
  сейчас передают `result.data`, сможет спросить «дай гистограмму», а не угадывать.

### 2.5 Адресация по роли у потребителя

```python
.detect_zones('zero_crossing', indicator_role='hist')      # новое
.detect_zones('zero_crossing', indicator_col='macd_hist')  # старое, продолжает работать
```

Пайплайн **сам знает** идентичность — он создавал индикатор в `with_indicator()`.
Ему достаточно роли, чтобы вычислить имя. Это и есть то, ради чего затевается
абстракция: пользователь перестаёт быть обязан знать строку.

## 3. Как решение закрывает каждый дефект

| Дефект | Чем закрывается |
|---|---|
| **D1** — три соглашения | Слаг вычисляется в одном месте из `(name, params)`. Индивидуальные `get_output_columns()` перестают изобретать имена. |
| **D1** — столкновение экземпляров | Параметры в слаге ⇒ MACD(12,26,9) и MACD(5,35,5) имеют разные имена и сосуществуют. |
| **D2** — затирание входных колонок | Точка слияния сверяется со схемой и с уже занятыми именами. Сегодня это предупреждение (G17, этап A); после ввода схемы конфликт **становится ошибкой** — переходного периода между ними не нужно (§5), достаточно того, что слаг делает столкновение с «сырым» `macd` из выгрузки практически невозможным, и оставшиеся случаи — действительно ошибки. |
| **D3** — ложная подпись | Имена берутся из **фактического** вызова, а не из кэша регистрации. Для библиотек — уважать имя, которое вернула библиотека (см. §4.3). |
| Незакреплённый контракт | `get_output_columns()` выводится из объявления ролей, а `calculate()` собирает кадр по нему же — расхождение становится невозможным по конструкции, а не по дисциплине. |

## 4. Принятые решения (2026-08-24)

Раздел был списком открытых вопросов; закрыты все. Оставлен как запись того, что решено
и почему.

### 4.1 Разделитель и форма слага — двойное подчёркивание

`macd_12_26_9__hist`. Одиночное `_` делает обратный разбор неоднозначным.

**Важная оговорка, которой в первой редакции не было.** Разбор имени обратно **не является
основным путём и не должен им стать**. Смысл абстракции в том, что отображение
«колонка → (индикатор, роль)» живёт в схеме-спутнике (§2.4), а не в строке. Парсинг нужен
единственно там, где схема потеряна: пользователь сохранил кадр в CSV и загрузил обратно.

Поэтому в коде этот путь помечается как **деградированный**: он обязан сообщать, что
восстановил роли догадкой, а не знанием. Без этой пометки через год строка снова станет
источником истины, и G8 придётся чинить заново — уже под новым номером.

### 4.2 `bb` против `bbands` — слаг от `bbands`

Слаг обязан быть выводим из имени индикатора, иначе абстракция не решает исходную задачу
(пользователь по-прежнему обязан лезть в исходник). `bb_*` не переезжает в слой
совместимости, как предлагалось в первой редакции, а **просто исчезает** вместе со всеми
точками использования — см. §6.

### 4.3 Библиотечные индикаторы — уважать имя библиотеки

**Уже сделано этапом A** (`43f071a`): мы перестали переименовывать то, что вернула
pandas-ta. Причина принципиальная: D3 — дефект «мы уничтожаем корректную информацию»,
и лечить его другим переписыванием значило бы повторить ошибку в другой обёртке.
Единообразие даёт схема, а не строка.

### 4.4 Словарь ролей — замкнутый, с точкой расширения

`line`, `signal`, `hist`, `upper`, `middle`, `lower`, `width`, `percent`, `value`;
пользовательский индикатор может зарегистрировать свою роль.

Это **зеркально** решению по типам зон (G20 §1), и симметрия здесь не косметическая, а
проверочная. Один принцип на оба гэпа:

> **Закрыто то, на чём дискриминирует универсальный код; открыто то, что придумывает
> предметная область.**

У типов зон открыты *имена* (`bull`, `overbought`, `regime_a` — сколько угодно), закрыты
*свойства* (`polarity`, `counterpart`, `display`). У колонок открыты *имена колонок*
(`RSI_50`, `MACD_12_26_9`, что угодно от библиотеки), закрыты *роли*. Роль и есть свойство.
Если в каком-то из двух мест захочется сделать наоборот — это признак, что дефект
воспроизводится, а не чинится.

### 4.5 Кэш

`CACHE_VERSION` (сейчас 6) и `CACHE_SCHEMA_VERSION` (сейчас 6) **обязаны** быть подняты в
том изменении, где меняется набор имён колонок. Жёсткий инвариант проекта, не предмет
выбора.

### 4.6 Два класса `IndicatorConfig` — развести до `IndicatorId`

Первая редакция называла это «побочным» и предполагала, что второй класс внутренний.
Проверено: **оба экспортируются публично** — `bquant.indicators.IndicatorConfig`
(`base.py:28`, поля `name/parameters/source/columns/description`) и
`bquant.analysis.zones.IndicatorConfig` (`pipeline.py:62`, поля `source/name/params`).
Вне пакета: 19 употреблений первого, 15 второго.

**Решение:** тот, что в `zones`, переименовывается в **`IndicatorSpec`**, а поле `params` —
в `parameters`. Имя точнее по смыслу (это не конфигурация индикатора, а *заявка посчитать*
индикатор), и употреблений меньше. Без алиасов; все 15 точек правятся в том же изменении.

Делается **первым шагом этапа B** — иначе `IndicatorId` придётся строить из двух
несовместимых источников.

## 5. Совместимость: механизм переходного периода снят (2026-08-24)

Первая редакция проектировала **двойную эмиссию**: индикатор отдаёт и каноническую
колонку, и старую, обращение по старой поднимает `DeprecationWarning`, снятие — отдельным
релизом. Механизм снят целиком.

**Причина.** Он защищал внешних пользователей, которых у проекта нет. Цена при этом
вполне реальная: удвоенный набор колонок в каждом кадре, предупреждения, которые
средствами pandas **невозможно поставить на само обращение** `df['macd_hist']` (только на
входы пакета — это признавалось честно и в первой редакции), плюс отдельный релиз-этап на
снятие и всё время до него — код, который надо помнить.

**Чем заменено.** Переименование доводится до конца в одном изменении, вместе со всеми
точками использования: `indicator_col='macd_hist'` — 95 мест, `'RSI_14'` — 15, всё в
`tests/`, `docs/`, `examples/`, `research/`. `devref/` и `changelogs/` **не трогать** — это
история.

Страховкой служит не переходный период, а механическая проверка, и она строже: полный
сьют плюс `tests/unit/test_docs_parity.py`, который сам находит отставшие доки. Отсутствие
предупреждения об устаревании компенсируется тем, что забытая точка использования не
доживает до релиза — она падает.

**Что переходный период всё равно не защищал и о чём надо помнить отдельно:**

- **Кэш** — закрывается bump'ом `CACHE_VERSION`/`CACHE_SCHEMA_VERSION` (§4.5), старые
  записи просто не читаются.
- **Сохранённые артефакты рисёрча** (CSV/parquet с колонками старых имён) — здесь схема
  утрачена по построению, и это ровно тот случай, ради которого в §4.1 сохранён
  деградированный разбор имени. Двойная эмиссия им бы тоже не помогла: файл уже записан.

### Этап C — абстракция (**выполнен 2026-08-24, разделён надвое**)

**Отступление от исходного плана, с причиной.** В первой редакции этап C одновременно

зелёным сьютом и проверяем против прежнего поведения». Поэтому C разделён:

  `indicator_role=`. Сьют 1291 passed / 3 skipped. Пользовательская польза уже здесь:
  вызывающий перестал быть обязан знать строку — ради чего абстракция и затевалась.
- **C2 (следующий шаг):** перевод имён на слаги вместе с потребителями и документацией,
  то есть C2 = бывший «этап D».

## 8. Отвергнутые альтернативы

**Просто переименовать в `macd_12_26_9_hist`.** Закрывает D1 и столкновения, но
пользователь по-прежнему обязан знать точную строку. Меняем одно угадывание на другое,
более длинное, ломая при этом всех. Не решает корень — отображение «колонка → смысл»
по-прежнему нигде не живёт.

**Не сливать в один кадр, возить `IndicatorResult`.** Идеологически чище, но переписывает
весь пайплайн и всю визуализацию разом, без промежуточных состояний. Радиус
несоразмерен выигрышу; схема-спутник даёт то же знание при кратно меньшей правке.

**`MultiIndex`-колонки `(indicator, role)`.** Выразительно и решает всё сразу, но ломает
любой пользовательский код, работающий с кадром, и плохо переживает сериализацию в CSV.
Для библиотеки, чей результат люди выгружают наружу, цена слишком высока.

**Оставить как есть, задокументировать.** Отвергнуто из-за D3: колонка, утверждающая
неверные параметры, — это дефект корректности, а не соглашения, и документацией не
лечится.
