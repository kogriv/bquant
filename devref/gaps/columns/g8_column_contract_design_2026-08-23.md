# G8 — контракт выходных колонок: проектное решение (2026-08-23)

**Статус:** проект, не реализовано. Согласован объём и порядок работ; код не тронут.
**Разбор дефектов:** `g8_column_contract_measurement_2026-08-23.md`
**Замер:** `devref/gaps/columns/g8/g8_measure.py`

---

## 1. Что решаем

Три дефекта с общим корнем (нумерация из разбора):

- **D1** — три соглашения об именах, параметры теряются, экземпляры сталкиваются;
- **D2** — тихое затирание при слиянии в кадр (`pipeline.py:294-295`);
- **D3** — библиотечные колонки подписаны параметрами регистрации, а не вызова.

Корень: имя колонки совмещает **идентичность** (какой экземпляр посчитал) и **роль**
(что ряд означает), а отображением между ними никто не владеет.

### Чего решение обязано достичь

1. Имя колонки **однозначно** определяется индикатором и его параметрами.
2. Потребитель может получить нужный ряд, **не зная строки** — по роли.
3. Слияние в кадр **не затирает молча** ничего.
4. Существующий пользовательский код **не ломается в момент выхода** правки.

### Чего решение сознательно НЕ делает

- Не меняет **значения** индикаторов — только имена и способ адресации.
- Не трогает `devref/` и `changelogs/` — это история (288 вхождений).
- Не унифицирует имена **входных** колонок OHLCV — это отдельный контракт
  (`bquant/data/schemas.py`), у него свои потребители.
- Не переводит на роли внешние библиотеки целиком — pandas-ta имеет собственное
  соглашение, и его надо **уважать**, а не подменять (см. §4.3).

## 2. Абстракция

### 2.1 Идентичность — `IndicatorId`

Детерминированный слаг из имени и **нормализованных** параметров.

```python
@dataclass(frozen=True)
class IndicatorId:
    source: str                    # 'custom' | 'preloaded' | 'pandas_ta' | 'talib'
    name: str                      # 'macd', 'rsi', 'bbands'
    params: Mapping[str, Any]      # {'fast_period': 12, ...}

    @property
    def slug(self) -> str:
        """'macd_12_26_9', 'rsi_14', 'bb_20_2.0' — стабильно и воспроизводимо."""
```

Нормализация — существенная часть, а не деталь. Требования:

- **порядок параметров фиксирован** объявлением индикатора, а не порядком в `**kwargs`,
  иначе `MACD(fast=12, slow=26)` и `MACD(slow=26, fast=12)` дадут разные слаги;
- **дефолты подставляются явно** — `rsi()` и `rsi(period=14)` обязаны совпасть;
- **числа канонизируются** — `2` и `2.0` не должны расходиться (у pandas-ta `BBL_5_2.0_2.0`
  показывает, во что это выливается);
- **служебные параметры исключаются** — те, что не влияют на значения.

Информация **уже есть** и просто не используется: `CustomIndicator.__init__` получает
`(name, parameters)` и кладёт их в `IndicatorConfig.parameters`.

### 2.2 Роль — `OutputRole`

Индикатор объявляет выходы ролями, а не строками:

| Индикатор | Роли |
|---|---|
| MACD | `line`, `signal`, `hist` |
| Bollinger | `upper`, `middle`, `lower`, `width`, `percent` |
| RSI, SMA, EMA | `value` |

Роль — это то, что нужно потребителю. Детектору нужна «гистограмма», а не строка
`macd_hist`. Роли — **замкнутый словарь** на уровне пакета, а не свободный текст:
иначе получим ту же проблему этажом выше.

### 2.3 Имя колонки

```
{slug}__{role}        macd_12_26_9__hist,  bb_20_2.0__upper
{slug}                rsi_14                (единственный выход с ролью 'value')
```

Двойное подчёркивание разделяет идентичность и роль однозначно — имена индикаторов и
параметры сами содержат одиночные `_`.

### 2.4 Схема-спутник — `ColumnSchema`

После слияния в `DataFrame` объекты исчезают, остаются строки. Значит отображение
обязано пережить слияние.

```python
@dataclass
class ColumnSchema:
    """(IndicatorId, role) -> фактическое имя колонки в кадре."""
    entries: Dict[Tuple[IndicatorId, str], str]

    def column(self, indicator: IndicatorId, role: str) -> str: ...
    def roles_of(self, column: str) -> Optional[Tuple[IndicatorId, str]]: ...
```

Куда крепится:

- `IndicatorResult` уже имеет `config` и `metadata` — добавляем поле `columns: Dict[role, str]`;
- пайплайн копит `ColumnSchema` по мере расчёта индикаторов;
- `ZoneAnalysisResult` получает поле `column_schema`, и тогда визуализатор, которому
  сейчас передают `result.data`, сможет спросить «дай гистограмму», а не угадывать.

### 2.5 Адресация по роли у потребителя

```python
.detect_zones('zero_crossing', indicator_role='hist')      # новое
.detect_zones('zero_crossing', indicator_col='macd_hist')  # старое, продолжает работать
```

Пайплайн **сам знает** идентичность — он создавал индикатор в `with_indicator()`.
Ему достаточно роли, чтобы вычислить имя. Это и есть то, ради чего затевается
абстракция: пользователь перестаёт быть обязан знать строку.

## 3. Как решение закрывает каждый дефект

| Дефект | Чем закрывается |
|---|---|
| **D1** — три соглашения | Слаг вычисляется в одном месте из `(name, params)`. Индивидуальные `get_output_columns()` перестают изобретать имена. |
| **D1** — столкновение экземпляров | Параметры в слаге ⇒ MACD(12,26,9) и MACD(5,35,5) имеют разные имена и сосуществуют. |
| **D2** — затирание входных колонок | Точка слияния сверяется со схемой и с уже занятыми именами; конфликт — предупреждение (переходный период) → ошибка. Плюс слаг делает столкновение с «сырым» `macd` из выгрузки практически невозможным. |
| **D3** — ложная подпись | Имена берутся из **фактического** вызова, а не из кэша регистрации. Для библиотек — уважать имя, которое вернула библиотека (см. §4.3). |
| Незакреплённый контракт | `get_output_columns()` выводится из объявления ролей, а `calculate()` собирает кадр по нему же — расхождение становится невозможным по конструкции, а не по дисциплине. |

## 4. Решения, которые надо принять явно

### 4.1 Разделитель и форма слага

Предлагается `macd_12_26_9__hist`. Альтернатива — оставить одиночное `_`
(`macd_12_26_9_hist`), тогда парсинг обратно (`roles_of`) становится неоднозначным.
**Рекомендация:** двойное подчёркивание; неоднозначность разбора дороже эстетики.

### 4.2 Что делать с `bb` против `bbands`

Сейчас индикатор зовётся `bbands`, а колонки начинаются с `bb`. Слаг обязан быть
выводим из имени индикатора, иначе смысл теряется. **Рекомендация:** слаг от `bbands`;
`bb_*` уходит в слой совместимости.

### 4.3 Библиотечные индикаторы: свой слаг или имя библиотеки

Два варианта, и выбор неочевиден.

- **(a) Уважать имя библиотеки.** pandas-ta уже даёт `RSI_50`, `MACD_12_26_9` —
  корректно и привычно её пользователям. Тогда D3 чинится тем, что мы **перестаём
  переименовывать**, и всё.
- **(b) Приводить к своему слагу.** Единообразие внутри bquant, но мы теряем связь с
  документацией pandas-ta и снова переписываем чужие имена — ровно то, за что D3
  и критикуется.

**Рекомендация: (a).** Причина принципиальная: D3 — это дефект «мы уничтожаем корректную
информацию». Лечить его другим переписыванием — повторить ошибку в другой обёртке.
Схема (§2.4) при этом всё равно даёт единый способ адресации по роли, независимо от того,
как называется колонка физически. **Единообразие даёт схема, а не строка.**

### 4.4 Словарь ролей

Замкнутый перечень (`line`, `signal`, `hist`, `upper`, `middle`, `lower`, `width`,
`percent`, `value`) или свободные строки? **Рекомендация:** замкнутый, с явной точкой
расширения для пользовательских индикаторов, иначе роли деградируют в те же
неугадываемые литералы.

### 4.5 Кэш

Меняется набор имён колонок ⇒ меняется семантика сериализованного результата.
`CACHE_VERSION` (сейчас 6) и `CACHE_SCHEMA_VERSION` (сейчас 6) **обязаны** быть подняты
в том же изменении. Это жёсткий инвариант проекта.

### 4.6 Побочное: два класса `IndicatorConfig`

`bquant/indicators/base.py:28` (поля `name/parameters/source/columns/description`) и
`bquant/analysis/zones/pipeline.py:62` (поля `source/name/params`) — **разные классы с
одинаковым именем**, причём один зовёт параметры `parameters`, другой `params`. Это тот
же корень: контрактом никто не владеет. Развести имена стоит в рамках этой же работы —
иначе `IndicatorId` придётся строить из двух несовместимых источников.

## 5. Совместимость

Ломать пользователей в момент выхода нельзя: `indicator_col='macd_hist'` встречается в
доках/примерах/рисёрче 95 раз, `'RSI_14'` — 15 раз, и это только у нас.

**Механизм — двойная эмиссия.** На переходный период индикатор отдаёт **обе** колонки:
каноническую и старую. Старая — не копия, а ссылка на те же данные, чтобы не удваивать
память на широких кадрах. Обращение по старому имени поднимает `DeprecationWarning`
с указанием нового.

Ограничение, которое надо признать честно: перехватить обращение `df['macd_hist']`
средствами pandas без подмены типа кадра нельзя. Значит предупреждение реально ставится
**на входах пакета** (`indicator_col=`, API визуализации), а не на любом обращении к
`DataFrame`. Пользователь, который сам лезет в колонку, узнает о смене из CHANGELOG и
из того, что рядом появилась новая колонка. Обещать больше было бы неправдой.

Снятие старых имён — **отдельным релизом** после переходного, не в том же.

## 6. Порядок работ

Разделён так, чтобы каждый этап имел самостоятельную ценность и мог быть выпущен
отдельно.

### Этап A — не ломает ничего (кандидат в 0.0.6)

1. **Тест-пин согласованности**: для каждого индикатора
   `get_output_columns() == calculate(data).data.columns`. Фиксирует базу до рефакторинга.
2. **Починка D3**: перестать затирать имена, которые вернула библиотека. Это исправление
   вранья, а не смена соглашения. Побочный эффект: `RSI_50` вместо `RSI_14` — формально
   видимое изменение, поэтому идёт в CHANGELOG как `Fixed` с явным примечанием.
3. **Предупреждение при затирании** в точке слияния (D2). Ничего не ломает, делает
   проблему видимой — в том числе для пользователей, у которых она уже есть.
4. Тесты на всё перечисленное.

### Этап B — вводит абстракцию (минорный релиз)

5. `IndicatorId` + нормализация параметров + `OutputRole` + `ColumnSchema`.
6. Развести два `IndicatorConfig` (§4.6).
7. Индикаторы объявляют роли; `get_output_columns()` выводится, а не пишется руками.
8. Двойная эмиссия старых имён + `DeprecationWarning` на входах пакета.
9. `indicator_role=` в детекции и стратегиях, рядом с существующим `indicator_col=`.
10. `CACHE_VERSION`/`CACHE_SCHEMA_VERSION` +1.

### Этап C — переводит потребителей

11. Визуализация (`charts.py`, `zones.py` — 14 мест) на схему.
12. `zone_features.py` (7 мест, включая MACD-специфичную ветку) на роли.
13. Доки, примеры, рисёрч — на роли. `devref/` и `changelogs/` **не трогать**.

### Этап D — снятие (следующий релиз после C)

14. Убрать двойную эмиссию и старые имена.

**Этап A самостоятелен** и улучшает положение, даже если B–D отложатся.

## 7. Чем закрывается от рецидива

- Тест-пин §6.1 — расхождение объявленного и фактического.
- Тест на детерминированность слага: перестановка `**kwargs` и подстановка дефолтов
  не меняют имя.
- Тест на столкновение: два экземпляра одного индикатора в одном кадре сосуществуют.
- Тест на D2: расчёт индикатора поверх кадра с занятым именем предупреждает.
- Тест на D3: `rsi(length=50)` даёт колонку, чьё имя согласуется со значениями.
- `g8_measure.py` остаётся в репо как воспроизводимый замер «до/после».

## 8. Отвергнутые альтернативы

**Просто переименовать в `macd_12_26_9_hist`.** Закрывает D1 и столкновения, но
пользователь по-прежнему обязан знать точную строку. Меняем одно угадывание на другое,
более длинное, ломая при этом всех. Не решает корень — отображение «колонка → смысл»
по-прежнему нигде не живёт.

**Не сливать в один кадр, возить `IndicatorResult`.** Идеологически чище, но переписывает
весь пайплайн и всю визуализацию разом, без промежуточных состояний. Радиус
несоразмерен выигрышу; схема-спутник даёт то же знание при кратно меньшей правке.

**`MultiIndex`-колонки `(indicator, role)`.** Выразительно и решает всё сразу, но ломает
любой пользовательский код, работающий с кадром, и плохо переживает сериализацию в CSV.
Для библиотеки, чей результат люди выгружают наружу, цена слишком высока.

**Оставить как есть, задокументировать.** Отвергнуто из-за D3: колонка, утверждающая
неверные параметры, — это дефект корректности, а не соглашения, и документацией не
лечится.
