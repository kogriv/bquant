# G55 — Валидация: вердикты без смысла и флаг без действия

**Заведён:** 2026-09-04, из аудита качества (AQ-005, AQ-006, AQ-007, AQ-009).
**Статус:** ✅ закрыт 2026-09-04 — метрика описывается `MetricSpec`, вердикт знает направление и нормировку; `.analyze(validation=True)` исполняется.

---

## 1. Что было — замер

Все четыре пункта аудита воспроизведены на коде до правки (`ValidationSuite` по
умолчанию, 400 баров, разбиение 70/30):

| Вход | Ответ было | Ответ должен быть |
|---|---|---|
| стационарный процесс, ровно 1 «зона» на 10 баров (28 на 280 барах, 12 на 120) | деградация **57.1 %**, `success=False` | частота та же, держится |
| то же, walk-forward 200/50 | деградация **75 %**, `success=False` | держится |
| метрика «больше — лучше» выросла вдвое на тесте | −100 %, **`success=False`** | улучшение, держится |
| метрика «меньше — лучше» упала вдвое на тесте | 50 %, **`success=False`** | улучшение, держится |
| `train=0`, `test=7` | **0 %, `success=True`** | процента от нуля нет — отказ |
| Monte Carlo, `percentile_real` | **40.0** = значение метрики | ранг в распределении, 50 |
| пайплайн `.analyze(validation=True)`, 77 зон | `validation_results=None`, в метаданных ничего | проверка исполнена или названа причина |

Самое неприятное — первая строка. G39 (2026-08-31) починил в этом модуле подмену
отсутствующей метрики нулём, и README привёл как правильный ответ ровно эти
**28 → 12, 57.1 %, `False`**. Один вердикт из ничего сменился другим: не «0 %, потому что
не измерили», а «57 %, потому что окна разной длины». Оба — о чём угодно, кроме процесса.

## 2. Почему это форма «проверка не видит проверяемого»

Набор сравнивал число по имени ключа. Имени не хватало трижды: не сказано, счётчик это
или частота (тогда окна разной длины несравнимы); не сказано, куда «лучше» (тогда
`abs(change)` называет улучшение провалом); не сказано, что делать с нулём в базе (тогда
`0.0` читается как «не изменилось»). В Monte Carlo ключ `percentile_real` хранил
`np.percentile(sims, доля)` — значение, подписанное как ранг, и `success` требовал «выше
p95» для любой метрики.

В пайплайне флаг проходил builder → пресеты → `ZoneAnalysisConfig` → `UniversalZoneAnalyzer`,
где стояло `logger.info("Validation requested but not executed")` и `validation_results = None`.
`None` неотличим от «не просили». Причина, по которой это никогда не было реализовано,
архитектурная: анализатор получает готовые зоны и не владеет детекцией, а валидация обязана
заново прогнать детекцию на каждом окне.

Проверки: 26 тестов набора передавали `total_zones = len(data) // 10` — стационарный процесс — и
утверждали `isinstance(result.success, bool)`. Ни один не спрашивал, **каков** вердикт.

## 3. Что сделано

- **`MetricSpec(key, direction, per_bar)`** — обязательный аргумент всех четырёх методов,
  умолчания нет. `direction`: `higher_is_better` / `lower_is_better` / `stable`. `per_bar`:
  делить на число баров окна — обязательно для счётчиков.
- **Деградация в направлении метрики:** положительное — хуже, отрицательное — лучше;
  вердикт односторонний для направленных метрик и по модулю для `stable`. Нулевая база при
  ненулевом тесте — `AnalysisError`, называющая оба значения; ноль против нуля — измеренное
  «без изменений».
- **Monte Carlo:** `percentile_rank` — средний ранг реального значения среди симуляций
  (0–100); `success_rule` называет правило (`real > p95` / `real < p05` / вне `[p2.5, p97.5]`);
  пороги p2.5/p5/p95/p97.5 в метаданных. `percentile_real` удалён.
- **Sensitivity:** `best`/`worst` по направлению; для `stable` их нет (`None`). Стабильность
  через `|mean|`; нулевое среднее при разбросе — отказ.
- **Пайплайн:** `ZoneAnalysisPipeline._validate` — out-of-sample проверка настроенной
  детекции на подготовленном кадре, метрика `MetricSpec('total_zones', 'stable', per_bar=True)`,
  разбиение 70/30, порог — у `ValidationSuite` анализатора (DI). `result.validation_results =
  {'out_of_sample': …}`; `result.metadata['validation']` — `executed` / `failed` (+`reason`) /
  `not_requested`. Параметр `run_validation` у `UniversalZoneAnalyzer.analyze_zones` удалён —
  он принимался и не делал ничего. `CACHE_VERSION` 22 → 23.
- **Тесты:** `tests/unit/test_validation_knows_what_it_compares.py` — 16 проверок по всем
  четырём пунктам и трём состояниям пайплайна. Существующие 26 + 5 переведены на `MetricSpec`;
  проверка G39 «реальная деградация» теперь строится на процессе, который **действительно**
  падает вдвое на тесте, а не на длине окна.

Мутации (каждая восстановлена после прогона):

| Мутация | Краснеет |
|---|---|
| `per_bar` игнорируется | 4 (два стационарных, ранг, пайплайн) |
| `abs()` для всех направлений | 2 (улучшение, lower_is_better) |
| нулевая база → `0.0` | 1 |
| ранг → `np.percentile(sims, доля)` | 2 (ранг, вердикт по направлению) |
| пайплайн не вызывает `_validate` | 2 (`executed`, `failed`) |

## 4. Замер после

| Вход | Ответ |
|---|---|
| стационарный процесс, out-of-sample / walk-forward | 0.1 vs 0.1 на бар, 0 %, держится |
| «больше — лучше» ×2 на тесте | −100 %, держится; под `lower_is_better` — +100 %, провал; под `stable` — провал |
| `train=0`, `test=7` | `AnalysisError: … train value is 0 and the test value is 7.0` |
| Monte Carlo, стационарный | `real_value=0.1`, `percentile_rank=50.0` |
| пайплайн на `tv_xauusd_1h`, MACD/hist | `executed`, 52 зоны на 700 барах против 26 на 300: 0.074 vs 0.087 на бар, −16.7 %, держится. По счётчикам было бы «падение вдвое» |

## 5. Цена

- Сигнатуры четырёх методов: `metric_key: str = 'total_zones'` → `metric: MetricSpec`,
  обязательный, третьим аргументом. Прежний вызов падает `TypeError`.
- `UniversalZoneAnalyzer.analyze_zones(run_validation=…)` — параметра нет.
- Ключи метаданных Monte Carlo: `real_metric_value` → `real_value`, `percentile_real` → нет,
  `percentile_rank` добавлен. Остальные методы: добавлены `metric`, `train_value`, `test_value`.
- Кэшированные результаты v22 не читаются.

## 6. Чего не сделано

- Пайплайн умеет только out-of-sample по частоте зон с фиксированным разбиением 70/30.
  Свою метрику, walk-forward или Monte Carlo — вызовом набора вручную; свой порог — через
  `validation_suite` анализатора. Расширять `.analyze(validation=…)` до спецификации
  проверки не стал: одна честная проверка лучше конфигурационного зоопарка без потребителя.
- «Statistical comparison» (доверительные интервалы вместо относительного порога) из
  предложения аудита не введено — порог остался относительным, но теперь на сравнимых
  величинах.
