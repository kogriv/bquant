# G82. Жёсткая смерть в широком поиске не оставляла ничего, с чем работать

**Дата:** 2026-09-12
**Тип:** observability (сохранность улик) + внешний дефект
**Приоритет:** 🟠 Medium — находка есть, а входа к ней нет
**Статус:** 🟠 частично — наша половина закрыта (кадр выгружается и поднимается артефактом);
аборт внутри `pandas-ta` остаётся открытым наблюдением, потому что без входа о нём нечего
сообщать вверх по течению
**Найдено:** первым же прогоном недельного CI (`weekly fresh resolution`, 2026-09-12,
плечо pandas-2)

---

## 1. Что случилось

Первый прогон нового workflow дал красное на плече pandas 2:

```
Fatal Python error: Aborted
Current thread ...
  File ".../bquant/indicators/library/pandas_ta.py", line 433 in calculate
  File ".../bquant/analysis/zones/strategies/swing/zigzag.py", line 104 in _swing_context
  ...
  File ".../tests/unit/test_invariants_hold_on_generated_data.py", line 252
        in test_zone_invariants_hold_on_a_wide_search
Aborted (core dumped) — код возврата 134
```

Плечо pandas 3 прошло полностью. Перезапуск того же задания прошёл зелёным.

Разрешения на обоих плечах совпадают во всём, кроме pandas (3.0.5 / 2.3.3): `pandas-ta`
0.4.71b0, `numpy` 2.2.6, `scipy` 1.18.1, `hypothesis` 6.168.0 — то есть дело не в версии
библиотеки, а во **входе**.

## 2. Здесь два разных факта, и смешивать их нельзя

**(а) `pandas-ta` уводит интерпретатор в abort на каком-то допустимом кадре OHLCV.** Не
исключение — `abort()` изнутри скомпилированного кода. Наш `try/except Exception` вокруг
`zigzag.calculate` такого не ловит **в принципе**: аккуратно написанный отказ («ZigZag global
pass could not run… иначе успешный прогон с нулём свингов неотличим от отсутствия свингов»)
в этом режиме недостижим. Процесс умирает раньше, чем мы получаем управление.

**(б) Наш широкий поиск терял находку.** `WIDE` объявлен с `derandomize=False` — намеренно:
он затем и широкий, чтобы каждый прогон пробовал формы, которых не пробовал никто. Цена в
том, что находка **не воспроизводится повторным запуском**, а при жёсткой смерти вместе с
процессом погибает и контрпример: `hypothesis` не успевает ни сжать пример, ни напечатать его.
Осталась трассировка без входа — то есть знание, что дефект есть, и никакой возможности с ним
что-либо сделать.

Второе — наше, и закрыто здесь. Первое без второго не закрывается: сообщать вверх по течению
«иногда падает на каких-то данных» нечего.

## 3. Заодно: докстрока файла утверждала неверное

Шапка `test_invariants_hold_on_generated_data.py` говорила: «seed фиксирован, поэтому красный
тест воспроизводится». Для бюджета по умолчанию (`derandomize=True`) это правда; **для
широкого поиска — нет**, и именно он находит редкое. Утверждение было верным ровно про тот
режим, который ничего нового не пробует. Переписано с разделением режимов.

## 4. Что сделано

`_record_wide_example(frame)` — выгрузка пробуемого кадра **до** проверки:

* пишется в файл, а не в `print`: захваченный pytest'ом вывод при `abort()` теряется вместе
  с процессом;
* `flush` + `fsync`: буфер теряется тоже;
* перезаписывается на каждом примере — нужен **последний**, тот, на котором умерли;
* включается переменной `BQUANT_WIDE_EXAMPLE_DUMP`. Без неё запись не делается: локальному
  прогону мусор в дереве не нужен, а CI переменную ставит и поднимает файл артефактом
  `wide-example-<плечо>` шагом `if: failure()`.

## 5. Проверено

| проверка | результат |
|---|---|
| Без переменной файл не появляется | файла нет |
| С переменной файл появляется | есть |
| Файл читается обратно как валидный кадр | `(60, 5)`, колонки `open/high/low/close/volume`, индекс возрастающий |

Обратное чтение проверено намеренно: файл, который есть и не читается, — это та же пустота,
только с именем.

## 6. Что осталось открытым

Аборт `pandas-ta`. Дальнейший шаг определён и не требует догадок: **следующее срабатывание
принесёт кадр артефактом**, и тогда появится минимальный вход — с ним можно и сузить свою
сторону (например, отказывать до вызова библиотеки на форме, которая её убивает), и завести
вопрос вверх по течению. До этого ни то, ни другое не обосновано.

Отдельно названо, чего эта правка **не** даёт: она не делает пакет устойчивее. Она делает
следующее падение пригодным для разбора.
