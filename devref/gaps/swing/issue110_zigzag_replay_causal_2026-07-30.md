# Issue #110 — ZigZag `confirmation_index` не replay-causal (репейнтинг под усечением)

**Дата:** 2026-07-30 · **Issue:** [#110](https://github.com/kogriv/bquant/issues/110) · **Статус:** ✅ ZigZag закрыт (generic-остатки — трекнуты)

## 0. РЕЗУЛЬТАТ (по прогону)

- **B оказался рабочим и это НЕ срез угла:** pandas-ta `backtest=True` — **строго replay-safe** поток
  (132 пивота на встроенном сэмпле, **0 changed / 0 disappeared** под усечением; лаг детекции 1–17 баров,
  **не фиксированный** — подтверждает, что `+legs` неверен; будущего не видит). Это «backtest-safe event
  stream» из ишью, а не заплатка.
- **Фикс:** `calculate_global` → `backtest=True`; `_confirmation_index` = дивиденс-ретрейс (без floor);
  **первый пивот наследует confirmation второго** (детектор не эмитит ничего до 2-й свинги — первые два
  становятся наблюдаемы вместе; эмпирически это единственная оставшаяся утечка).
- **Оракул:** repaint-нарушения ZigZag на сэмпле **35% → 0%** (через реальный код-путь), стабильно на
  legs∈{2,3,5}. Схема `CACHE_VERSION` 2→3.
- **Generic-контракт:** find_peaks (**+2 бара** лаг scipy-prominence, 3 нарушения) и pivot_points
  (**warm-up-edge** репейнт, 1) — **пред-существующие** мелкие остатки (я их не трогал), зафиксированы
  оракулом как `xfail(strict=True)` → станут регресс-детектором, xpass при починке. Это **не** предмет
  #110 (ZigZag), вынесено в generic-follow-up.
- **Тесты:** новый `test_swing_replay_causal.py` (2 passed ZigZag + 2 xfail generic); обновлён
  `test_zigzag_confirmation_index_causal` под новую (корректную) семантику первого пивота; свинг/зоны/кэш
  прогон — без регрессий.
- **Downstream:** пересбор когорт J1/J2/Z6/J4 — вне bquant, зафиксировать в ишью.
**Файлы ядра:** `bquant/analysis/zones/strategies/swing/zigzag.py` (`calculate_global`,
`_confirmation_index`), `bquant/analysis/zones/models.py` (`SwingPoint`), `bquant/analysis/zones/cache.py`

## 1. Диагноз

`SwingPoint.confirmation_index` сегодня = время **дивиденс-ретрейса** на **финальном** полноисторическом
пивоте (peak: первый бар, где `low` упал на `deviation` ниже цены пивота; ограничен `next_position`).
Это убрало утечку `amplitude_to_next`, но **не** сделало последовательность пивотов наблюдаемой на этот
момент времени.

Дефолтный pandas-ta ZigZag — **центрированный/обратный** детектор (`nb_find_zz` от правого края,
`backtest=False`): при усечении сырого OHLC на `as_of` пивоты **добавляются / пропадают / заменяются**,
даже когда `confirmation_index <= as_of`. Итог (downstream-замеры, bquearch J1-R): full-history vs
replay-as-of разошлись в **19/26 (73%)** строк; пример — финал `195→201→205→206`, при `as_of=206`
усечённо `195→204`, совпадение только с `as_of=208`. Фиксированная `+legs`-задержка **не доказана**
(есть замена пивотов, не только задержка появления).

**Существующий тест бессилен по конструкции:** `test_zigzag_confirmation_index_causal` monkeypatch'ит
фиксированный список пивотов (`use_fake_zigzag_indicator`) и проверяет только дивиденс-скан — реальный
детектор под усечением он не гоняет.

## 2. Контракт (из ишью)

- Разделить **event time** (`SwingPoint.index` — когда пивот случился) и **detection/availability time**
  (`confirmation_index` — когда наблюдаем **и стабилен**); держать раздельными.
- `detection` **replay-safe**: пивот, объявленный доступным на `t`, идентичен при расчёте на `data[:t+1]`
  и на любом бóльшем расширении.
- Проверено **эмпирически** (усечение сырого OHLC), не фиксированной задержкой; adversarial right-edge
  (замена пивота, не только задержка).
- Обобщённо на прочие свинг-стратегии (find_peaks/pivot_points — тот же контракт).
- Бамп swing/cache-схемы (`CACHE_VERSION`) при смене сериализованной семантики.

## 3. Развилка подходов (обсуждено)

- **A. Онлайн/каузальный ZigZag** — свой детектор: бегущий экстремум, пивот подтверждается в момент
  ретрейса `deviation`. Каузален **по построению**, натив даёт (event_index, detection_index), не
  перерисовывает. Минус: набор пивотов расходится с pandas-ta → метрики меняются → бамп схемы + пересбор
  когорт вниз по потоку.
- **B. pandas-ta backtest-режим** — проверить, даёт ли `backtest=True` каузальный поток; если да —
  дешёвый фикс. (Проверяем в `venv_bquant`, там есть pandas-ta.)
- **C. Эмпирический detection-index** — сохранить набор пивотов pandas-ta, но для каждого посчитать
  минимальный `as_of`, где усечённый вывод стабилизируется (валидировать горизонтом, не `+legs`).
  Плюс: full-history набор не меняется (меньше урона). Минус: дорогой replay; детектор остаётся
  перерисовывающим (контракт чинится на выходе, не в детекторе).

**Решение по «полноценно»:** цель — **A** (каузальность по построению). **C** — запасной, если
дивергенция A с pandas-ta окажется неприемлемой (тогда full-history набор сохраняем, detection считаем
эмпирически). Выбор A/C фиксируем **после** оракула+B-чека (данные, не мнение).

## 4. План (approach-agnostic сначала)

1. **Оракул (тест-честности)** — новый `tests/unit/test_swing_replay_causal.py`: на встроенном
   `tv_xauusd_1h` (короткий, детерминированный, в сьюте) для каждой стратегии строим full-history
   контекст; на наборе `as_of`-чекпоинтов пере-прогоняем `calculate_global(df[:as_of+1])` и утверждаем:
   каждый свинг с `confirmation_index <= as_of` **идентичен** (index, price, type) полноисторическому и
   любому бóльшему префиксу. **+ синтетический adversarial-фикстур** (заведомая замена пивота у правого
   края). Гонится под pandas-ta (`venv_bquant`); `skipif` без него. **Ожидаемо: zigzag падает
   (воспроизводит баг), pivot_points проходит, find_peaks — под вопросом.**
2. **B-чек** — pandas-ta `backtest=True`/эквивалент: каузален ли? (в `venv_bquant`).
3. **Фикс A** — онлайн-каузальный ZigZag: `event_index` = бар экстремума, `detection_index` = бар
   ретрейса; хвостовой неподтверждённый экстремум → `detection_index=None`. Обновить `_confirmation_index`
   семантику / вынести детектор. find_peaks/pivot_points — прогнать через оракул (pivot_points фрактален и
   должен пройти; find_peaks — проверить edge).
4. **Схема** — `CACHE_VERSION` 2→3 (сериализованная семантика свингов изменилась).
5. **Тесты** — обновить `test_zigzag_confirmation_index_causal` (fake-pivot) под новую семантику; сьют
   зелёный; оракул зелёный для всех трёх.
6. **Пометка** — пересбор downstream-когорт (J1/J2/Z6/J4) вне bquant, зафиксировать в ишью/чейнджлоге.
   **Датасет:** для фикса и оракула хватает встроенного короткого + synthetic adversarial; полный 100k —
   только для воспроизведения 73% (характеризация, не требуется для корректности).
