# G42 — Схемная валидация подтверждала что угодно

**Заведён:** 2026-09-01, проходом по справочнику `docs/api/data/`.
**Статус:** ✅ **исправлен** в тот же день — заглушка заменена реализацией.

---

## 1. Замер

```python
validate_with_schema(get_sample_data('tv_xauusd_1h'), 'macd').is_valid   # True
```

`MACD_SCHEMA` требует колонки `macd_12_26_9__line`, `macd_12_26_9__signal`,
`macd_12_26_9__hist`. Ни одной из них во встроенном сэмпле нет. Вердикт —
«валидно». То же для `rsi` (требует `rsi_14`, в сэмпле колонка зовётся `rsi`), для
кадра из четырёх колонок без времени и объёма, и для кадра, где вместо цен стоят
строки.

## 2. Причина

`DataSchema.validate_dataframe()` была заглушкой:

```python
return DataValidationResult(
    is_valid=True, issues=[], warnings=[],
    stats={'rows': len(df), 'columns': len(df.columns)},
    recommendations=["Schema validation is not yet implemented"]
)
```

Признание, что проверки нет, в результате **было** — в `recommendations`. Это худшее
из возможных мест: поле читают, когда разбираются с отказом, а отказа не было. Тот, кто
спросил «валидно ли», получил `True` и дальше не смотрел.

Схема при этом несла всё необходимое для настоящей проверки: `required_fields`,
`optional_fields`, `field_types`, `validation_rules` — и `required_fields` у
индикаторных схем даже спрашиваются у самого индикатора (правка по `devref/gaps/columns/`).
То есть заглушкой была не схема, а один метод поверх готовых данных.

## 3. Побочная находка в том же файле

`IndicatorSchema('что-угодно-кроме-трёх-известных')` падал с
`AttributeError: 'IndicatorSchema' object has no attribute 'logger'`. Ветка
«индикатор неизвестен — оставляем схему без ограничений» была написана аккуратно,
с объясняющим комментарием, и **ни разу не исполнялась**: у `DataSchema` не было
логгера. Ошибку ловил бы первый же вызов с незнакомым именем.

## 4. Что сделано

Заглушка заменена реализацией по тем данным, которые схема и так несёт:

| Проверка | Результат |
|---|---|
| обязательное поле отсутствует | `issue`, `is_valid=False`, имена в `stats['missing_required']` |
| тип поля не числовой при объявленном `float`/`int` | `issue` с фактическим dtype |
| значения нарушают правило поля | `issue` + счётчик по колонкам в `stats['rule_violations']` |
| опциональное поле отсутствует | не отказ; отмечено в `stats['absent_optional']` |
| правило нельзя применить (нет значений) | `warning`, не молчание |

`DataSchema.__init__` получил логгер — ветка про неизвестный индикатор теперь работает
так, как описана.

Альтернатива — оставить заглушку, но заставить её **отказываться** отвечать
(`NotImplementedError`) — рассматривалась и отклонена: всё необходимое для настоящей
проверки в схеме уже лежало, и отказ вместо тридцати строк был бы выбором в пользу
меньшей работы, а не в пользу правды.

## 5. Тест

`tests/unit/test_schema_validation_forms_a_verdict.py` — девять проверок, включая пин
«вердикт не константа»: два кадра дают два разных ответа. На дореформенном коде падают
восемь из девяти.

## 6. След в документации и в рисёрч-скриптах

* `docs/api/data/schemas.md` писала «текущая реализация — заготовка» — оговорка верная
  и бесполезная: рядом стоял пример, печатающий `res.is_valid`, и печатал он `True`.
* `docs/api/data/README.md` называла `get_schema()`/`validate_with_schema()` «(пока stub)».
* `research/notebooks/01_data_schemas.py` **демонстрировал** ложный вердикт: шаг 5.3
  назывался «Валидация проблемных OHLCV данных» и печатал `Валидны: True`. Скрипт
  показывал дефект как возможность.
