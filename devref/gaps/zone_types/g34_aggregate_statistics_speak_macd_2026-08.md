# G34 — Агрегат зон говорит на языке MACD и отвечает нулями там, где вопрос не задан

**Заведён:** 2026-08-29 при последовательном проходе по докам (волна 1, `quick_start.md`).
**Статус:** ✅ **исправлен 2026-08-31**, вариант (c). Правка ломающая; прогон внешнего потребителя пройден в тот же день (`kogriv/bquearch#6`), релиз разблокирован.

---

## 1. Как нашли

Не поиском дефекта. Страница быстрого старта печатала

```python
print(f"Bull зон: {stats.get('bull_zones', 0)}")
print(f"Bear зон: {stats.get('bear_zones', 0)}")
```

на результате анализа **RSI**. Правило прохода — числа в доке получать прогоном; прогон
дал `Bull зон: 0`, `Bear зон: 0` при 64 найденных зонах.

Первый диагноз был про доку: ключей `bull_zones`/`bear_zones` в `statistics` нет вовсе,
а `.get(..., 0)` подставлял ноль, поэтому страница уверенно печатала два бессмысленных
числа. Это починено в доке. Но проверка того, что *есть* в агрегате, вскрыла второе.

## 2. Замер

```
RSI, threshold 70/30, встроенный сэмпл tv_xauusd_1h

найдено зон:   64      ('neutral': 32, 'oversold': 18, 'overbought': 14)

result.statistics['total_statistics']:
    total_zones        64        ← верно
    bull_zones_count    0        ← типа 'bull' нет в этом словаре вообще
    bear_zones_count    0
    bull_ratio        0.0
    bear_ratio        0.0
```

Четыре поля из пяти — нули, поданные как измерение. Читатель, глядящий в сводку,
заключает «направленных зон не найдено», тогда как верное утверждение —
**«такого деления у этого индикатора не существует»**.

Источник — `bquant/analysis/zones/zone_features.py:691`:

```python
bull_zones = df_features[df_features['zone_type'] == 'bull']
bear_zones = df_features[df_features['zone_type'] == 'bear']
```

Два строковых литерала из словаря одного семейства индикаторов, зашитые в универсальный
агрегат.

## 3. Почему это тот же дефект, что G20, а не новый

G20 закрывал ровно это: **словарь типов зон следует за индикатором**, и универсальный
код не вправе знать имена. Тогда правку довели до детекции и моделей — и не довели до
**агрегации**. Слой сдвинулся, литералы остались этажом выше.

Показательно, что соседний код в том же файле деградирует **честно**:
`duration_distribution` для RSI отдаёт только `overall`, без bull/bear-веток. То есть
правильное поведение в файле уже есть — оно просто не применено к `total_statistics`.

Разница между «ноль» и «не применимо» — та же, что между пустым ответом и хорошо
оформленной ложью. Пустой ответ виден; ноль неотличим от измерения.

## 4. Радиус

| Где | Что |
|---|---|
| `bquant/analysis/zones/zone_features.py:691-700` | производитель |
| `tests/unit/test_zones_analysis.py:253-254` | пин на `bull_zones_count == 5` — закрепляет текущую форму |
| `examples/04_comprehensive_analysis.py:128-129` | печатает `bull_ratio`/`bear_ratio` |
| `docs/user_guide/zone_analysis_result.md:350` | описывает поля |
| `docs/user_guide/cli.md:89` | схема JSON CLI содержит `bull_ratio`/`bear_ratio` |
| **внешний потребитель** | лаба читает статистику зон |

Последняя строка и определяет статус. Смена формы `total_statistics` — **ломающее
изменение для потребителя**, а в схеме `--json` у CLI эти поля объявлены, то есть
номер схемы придётся двигать.

## 5. Варианты (решение владельца)

**(a) Считать по фактическим типам.** Вместо двух литералов — распределение по всем
типам, которые встретились: `zones_by_type: {'neutral': 32, 'oversold': 18, ...}`.
Универсально, но меняет форму: `bull_zones_count` исчезает.

**(b) Оставить поля, но не выдумывать ноль.** `None` вместо `0`, когда типа нет в
словаре индикатора. Форма сохраняется, ложь уходит; но `None` в JSON-схеме — тоже
изменение, и потребитель, делающий арифметику, споткнётся.

**(c) И то, и другое:** `zones_by_type` как основное, а `bull_*`/`bear_*` остаются
только когда словарь индикатора их содержит.

Склоняюсь к **(c)**: она даёт универсальный ответ и не рушит MACD-путь, которым
пользуются сегодня. Но это смена контракта, и по правилам проекта она идёт через
потребителя: issue → его подтверждение на своём прогоне → релиз.

## 6. Как починено (2026-08-31)

Владелец выбрал вариант **(c)**.

`total_statistics` теперь всегда содержит `zones_by_type` и `ratios_by_type` —
распределение по **фактически встреченным** типам, каким бы ни был словарь
индикатора. Направленные поля остались, но только там, где эти типы есть:

```
MACD:  total_zones 32, zones_by_type {'bull': 16, 'bear': 16},
       bull_zones_count 16, bear_zones_count 16, bull_ratio 0.5, bear_ratio 0.5
RSI:   total_zones 64, zones_by_type {'neutral': 32, 'oversold': 18, 'overbought': 14}
       — направленных полей нет вовсе
```

Отсутствие ключа и ключ со значением `0` различимы программно, а `.get(field, 0)` у
старого потребителя вернёт тот же ноль, что и раньше, — то есть путь, которым сегодня
пользуются, не ломается молча.

**Номера схем сдвинуты оба:** `SUMMARY_SCHEMA_VERSION` CLI 1 → 2 (эта структура уходит
в `--json` как есть) и `CACHE_VERSION` 17 → 18 (запись v17 несёт нули там, где деления
не существует).

**Проверка** — `tests/unit/test_the_aggregate_speaks_the_indicator_vocabulary.py`,
двусторонняя намеренно: односторонняя («на RSI нет нулей») разрешила бы заодно
выбросить `bull_*` у MACD и сломать потребителя. Мутация: на коде до правки краснеют
3 из 4.

**Условие выпуска выполнено в тот же день** (`kogriv/bquearch#6`). Потребитель прогнал
свою граничную проверку — отпечаток эталонных зон не сдвинулся (3184 зоны,
`ee76e6ef3bec282a`), полный сьют 904 passed — и подтвердил грепом по всему репозиторию,
по всем типам файлов, что `total_statistics` не читает нигде: 0 совпадений по трём
именам. Он потребляет зоны, а не агрегат, поэтому смена формы его не задевает.

Отдельно он заметил, что четыре нуля на пороговом осцилляторе — это его собственный
класс дефекта: у него в тот же день нашлись пять чтений вида `if "macd" in z.data`,
которые после переименования колонок молча уходили в ветку «нет данных». Один силуэт,
разные слои.
