# G37 — NaN проваливает проверку «≥ 0», и зона теряет все метрики волатильности

**Заведён:** 2026-08-31 при последовательном проходе по докам (волна 2).
**Статус:** 🔴 открыт — правка кода, невелика.

---

## 1. Симптом

При включённой стратегии `volatility='combined'` часть зон остаётся без
`volatility_metrics`. На встроенном сэмпле (MACD по линии, 32 зоны) — три зоны
длительностью **1, 2 и 20** баров. Двадцать — не опечатка: зоны в 3 бара метрики
получают, а зона в 20 баров нет.

В логе — трейсбек:

```
AssertionError: bollinger_width_std must be >= 0
  bquant/analysis/zones/strategies/volatility/combined.py:104  result.validate()
  bquant/analysis/zones/strategies/base.py:472
```

## 2. Причина

`bb_length = 20`. У зоны ровно в 20 баров скользящее окно наполняется **один раз**:

```
непустых значений ширины Боллинджера: 1  →  width.std() = nan
```

Стандартное отклонение по одному значению — `NaN`. Дальше:

```python
assert self.bollinger_width_std >= 0
```

`NaN >= 0` — `False`. Проверка, написанная против отрицательных значений, срабатывает
на «величина не определена», роняет весь набор метрик зоны и сообщает об этом
неверными словами: величина не отрицательна, её просто нет.

## 3. Три отдельные вещи, которые здесь не так

1. **NaN трактуется как нарушение инварианта.** Неопределённость — не то же самое, что
   недопустимое значение. Правильный ответ для зоны, где окно не наполнилось, —
   отсутствие поля с причиной, а не падение всей группы метрик.
2. **Отказ виден только в логе.** В результате зона просто не имеет
   `volatility_metrics`, и отличить «не посчиталось» от «стратегия не включалась»
   нельзя. Тот же силуэт, что G35.
3. **Инвариант проверяется `assert`.** Под `python -O` он исчезнет вместе с проверкой —
   и вместо потери метрик получится `NaN`, уехавший в статистику.

## 4. Починка

- В `VolatilityMetrics.validate()` (`strategies/base.py:472`) отличать `NaN` от
  отрицательного значения: `NaN` — законное «не определено».
- Для зоны короче окна — не считать ширину вовсе и сказать об этом, по образцу тестов
  гипотез: они возвращают `error` с причиной, а не правдоподобное число.
- Проверки инвариантов перевести с `assert` на явную ветку с исключением.
