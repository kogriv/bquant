# G24 — Пакет пишет в каталог собственной установки, и падает там, где не может

**Заведён:** 2026-08-28 · **Статус:** 🟠 открыт → см. §6 план
**Обнаружено:** при проверке того, что реально получает пользователь опубликованной
0.0.7, — то есть *установкой из PyPI*, а не прогоном по исходникам.

---

## 1. Симптом

На чистом окружении, `pip install bquant==0.0.7`, каталог установки без права записи:

```
$ chmod -w site-packages
$ python -c "import bquant"
PermissionError: [Errno 13] Permission denied: '…/site-packages/logs'
$ bquant list
exit=1
```

Это **не деградация режима, а отказ импорта**. Ничего из пакета не доступно: ни
анализ, ни CLI, ни чтение конфигурации.

Когда права на запись есть, отказа нет — вместо него побочный эффект:

```
$ python -c "import bquant"
$ find site-packages -name bquant.log
site-packages/logs/bquant.log
```

Пакет завёл каталог и пишет свой лог **внутрь собственной установки**.

## 2. Причина

`bquant/core/config.py:15` и `:23–25`:

```python
PROJECT_ROOT = Path(__file__).parent.parent.parent
...
# Создаем директории если их нет
for directory in [PROCESSED_DATA_DIR, RESULTS_DIR, PROJECT_ROOT / "logs"]:
    directory.mkdir(exist_ok=True, parents=True)
```

`PROJECT_ROOT` вычисляется как «три уровня вверх от файла». В рабочей копии это корень
репозитория — там всё верно. У установленного пакета `bquant/core/config.py` лежит в
`site-packages`, и те же три уровня вверх дают **сам `site-packages`**.

Два независимых следствия:

1. **Каталоги создаются на импорте**, безусловно, до того как кто-либо попросил
   что-то записать. Поэтому отказ прав случается при `import bquant`, а не при попытке
   сохранить результат, — и обойти его вызывающему нечем.
2. **`LOGGING['log_file'] = PROJECT_ROOT / "logs" / "bquant.log"`** при
   `'file_logging': True` — то есть по умолчанию, у всех.

## 3. Форма дефекта

Та же, что у G8/G19/G20, только величина здесь не строка, а путь: **одно выражение
совмещает две разные вещи** — «корень исходного дерева, где живут данные и результаты
разработчика» и «каталог, куда установлен пакет». В рабочей копии они совпадают, и
поэтому промах не виден ровно тому, кто его правит. Расходятся они только у
пользователя.

Отсюда и то, что тесты молчали: сьют гоняется по рабочей копии, где `PROJECT_ROOT`
угадывает правильно. Проверить это можно **только** установкой.

## 4. Кого отсекает

Классы окружений, где каталог установки пользователю не пишется:

- системная установка (`/usr/lib/python3/dist-packages`) и любой managed Python;
- read-only слой контейнера, immutable-образы;
- слои AWS Lambda / любые «пакет распакован и только читается»;
- разделяемая на несколько пользователей установка.

Плюс всех остальных — загрязнением каталога установки и логом, который переживает
`pip uninstall` (каталог `logs/` создан не пакетным менеджером, в `RECORD` его нет).

## 5. Правильный образец уже есть в репозитории

`bquant/core/cache.py:260`:

```python
cache_dir = Path.home() / ".cache" / "bquant"
```

Дисковый кэш кладёт своё в пользовательский каталог и создаёт его **в момент записи**,
а не на импорте. `config.py` просто этому образцу не следует.

## 6. План

1. **Убрать создание каталогов с импорта.** Все, кто реально пишет, уже создают каталог
   сами (`core/utils.py:63`, `core/logging_config.py:191`, `core/cache.py:263`), так что
   цикл на импорте не нужен ничему.
2. **Развести два смысла пути.** `PROJECT_ROOT` остаётся тем, чем был, — местом, откуда
   читаются исходники. Записываемые по умолчанию каталоги (`RESULTS_DIR`,
   `PROCESSED_DATA_DIR`, `DATA_DIR`, лог) берутся из отдельного корня:
   - рабочая копия (в `PROJECT_ROOT` есть `pyproject.toml` и пакет `bquant/`) —
     корень репозитория, поведение разработчика **не меняется**;
   - установленный пакет — `$BQUANT_HOME`, иначе `~/.local/share/bquant`.
3. **Пины на установленную форму.** Проверять то, что нельзя проверить по рабочей копии:
   при `PROJECT_ROOT`, не похожем на чекаут, записываемые пути не лежат внутри пакета;
   импорт не создаёт ничего; корень определяется как чекаут только по признакам чекаута.
4. **Релиз.** Починка ценна только опубликованной: сейчас на PyPI лежит версия, которая
   у части пользователей не импортируется.

## 7. Смежное, найденное тем же прогоном

`bquant analyze` на опубликованной 0.0.7 **не создаёт график вообще** и возвращает `0`:

```
   ⚠️ Не удалось создать график
exit=0
```

Проглоченная причина — `Invalid frequency: 1H … Did you mean h?`: синтез оси времени
`pd.date_range(..., freq='1H')` не только выдумывал даты (см.
`../../architecture/p2a_cli_backlog_2026-08.md`), но и протух — в актуальной pandas
прописная `H` больше не частота. Строка удалена вместе с самим синтезом `64fb798`,
то есть в `main` этого уже нет; здесь отмечено как ещё один довод к релизу.
