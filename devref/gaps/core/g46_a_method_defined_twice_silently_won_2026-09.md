# G46. Метод объявлен дважды, второй молча победил — и параметр перестал действовать

**Дата:** 2026-09-02
**Тип:** correctness
**Приоритет:** 🟠 Medium — параметр публичного API не действовал, объект противоречил сам себе
**Статус:** ✅ исправлено
**Найдено:** при проходе по `docs/api/indicators/preloaded.md` (волна 3)

---

## 1. Что было

В теле `MACDPreloadedIndicator` метод `get_required_columns` объявлен **два раза
подряд**:

```python
def get_required_columns(self) -> List[str]:
    return self._required_columns.copy()      # запрошенное при создании

@classmethod
def get_required_columns(cls) -> List[str]:
    return cls.get_default_columns()          # ['macd', 'signal'], всегда
```

Python оставляет последнее определение в теле класса и не говорит ни слова. Побеждал
классовый двойник, поэтому `get_required_columns()` возвращал умолчания независимо от
того, что попросили при создании.

Дальше этим списком пользуются и `calculate()`, и `validate_data()`. Значит параметр
`required_columns` — документированный в трёх местах: в докстринге конструктора, в
`get_info()['usage_examples']` и на странице справочника — не действовал ни при
извлечении, ни при валидации.

## 2. Как это выглядело снаружи

Объект противоречил сам себе, потому что часть методов читала `_required_columns`
напрямую, а часть — через сломанный геттер:

```
MACDPreloadedIndicator(required_columns=['macd'])

get_required_columns()          -> ['macd', 'signal']   # умолчания
get_output_columns()            -> ['macd']             # запрошенное
get_output_roles()              -> {'line': 'macd'}     # запрошенное
config.columns                  -> ['macd']             # запрошенное
calculate().data.columns        -> ['macd', 'signal']   # умолчания
calculate().metadata            -> extracted_columns: ['macd']
```

Кадр несёт две колонки; объявление обещает одну; метаданные называют извлечённой одну;
роль есть только у одной. Потребитель, адресующийся по роли, вторую колонку не увидит
вовсе, хотя она в кадре есть.

Вторая половина хуже. С набором `['macd', 'signal', 'histogram']` на встроенном
сэмпле, где колонки `histogram` **нет**:

```
validate_data(data)  -> True
calculate(data)      -> кадр из двух колонок, без исключения
```

«Валидно» про набор, треть которого отсутствует. Тот же силуэт, что в G42, только
причина другая: там валидатор был заглушкой, здесь — проверял не тот список.

## 3. Почему сьют молчал

Он не молчал. Он это утверждал.

```python
def test_custom_columns_object_creation(self):
    """Тест создания объекта с кастомными колонками."""
    macd_custom = MACDPreloadedIndicator(required_columns=['macd', 'signal', 'histogram'])
    assert macd_custom.get_required_columns() == ['macd', 'signal']
```

Тест называется «создание объекта с кастомными колонками» и проверяет, что кастомные
колонки не действуют. Написан он был, судя по всему, подгонкой под наблюдаемое
поведение: получили `['macd', 'signal']`, записали `['macd', 'signal']`. Такая проверка
не просто пропускает дефект — она его закрепляет и заставит следующего чинить не код, а
её саму.

## 4. Что сделано

* Классовый двойник убран; остаётся метод экземпляра. `get_default_columns()` как был,
  так и есть — классовым методом, и умолчания берут у него.
* `metadata['nan_counts']` теперь всегда словарь. Было `... if nan_counts.any() else
  None`, то есть «ноль пропусков» и «не считали» выглядели одинаково, хотя считают
  здесь всегда.
* Проверка из §3 переписана на обратное утверждение.

## 5. Проверки

`tests/unit/test_preloaded_columns_are_the_columns_requested.py` — 11 проверок:
запрошенный набор в кадре (параметризовано по четырём наборам, включая перестановку и
колонку не из MACD), согласие пяти ответов объекта между собой, сохранность умолчаний,
отказ вместо «валидно» на отсутствующей колонке, покрытие ролями всех опубликованных
колонок, счётчик пропусков при нуле. На дореформенном коде краснеют 7 из 11.
