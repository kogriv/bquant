# G43 — Форма декоратора из инструкции проекта молча ломала функцию

**Заведён:** 2026-09-01, проходом по справочнику `docs/api/core/`.
**Статус:** ✅ **исправлен** в тот же день.

---

## 1. Замер

```python
from bquant.core.performance import performance_monitor

@performance_monitor
def f(data):
    return len(data)

f([1, 2, 3])
# <function performance_monitor.<locals>.decorator.<locals>.wrapper at 0x…>
```

Ожидалось `3`. Получена функция. Ни исключения, ни предупреждения.

## 2. Причина

`performance_monitor(enable_cpu=True, enable_memory=True)` — фабрика декораторов, то
есть требует **скобок**. Записанный без скобок, он получает саму функцию в аргумент
`enable_cpu` и возвращает `decorator`; декорированное имя становится `decorator`, и
вызов `f([1,2,3])` исполняет `decorator([1,2,3])`, который возвращает `wrapper`.

Результат — функция вместо числа, и никакого признака ошибки. Дальше эта величина
уходит в расчёт, сравнение или запись, и первое внятное сообщение появляется где-то
через несколько кадров стека, если вообще появляется.

## 3. Почему это хуже обычной опечатки

**Форма без скобок стояла в `AGENTS.md`** — в файле инструкций проекта, разделом
«Performance Monitoring», как образец для всех агентов и разработчиков:

```python
@performance_monitor
def my_analysis_function(data):
    # your code here
    pass
```

Пример был написан на функции, которая ничего не возвращает, поэтому подмена
результата в нём не проявлялась: `pass` возвращает `None`, а сломанный декоратор
возвращает `wrapper` — и разницу видно только у функции, чей результат кому-то нужен.
Образец был безопасен ровно в том виде, в каком его никто не применяет.

Та же форма стояла и в `docs/api/core/README.md`, и в перечне «быстрого поиска» той же
страницы — как `@performance_monitor()`, то есть в двух видах на одной странице.

## 4. Что сделано

`performance_monitor` принимает обе формы:

```python
@performance_monitor                                  # работает
@performance_monitor()                                # работает
@performance_monitor(enable_cpu=False)                # работает
performance_monitor(True)                             # TypeError с объяснением
```

Флаги переведены в keyword-only, поэтому позиционный аргумент теперь может быть только
декорируемой функцией; если он не вызываемый — `TypeError`, называющий правильную
запись. Молчаливой ветки не осталось.

## 5. Тест

`tests/unit/test_the_monitor_decorator_works_written_either_way.py` — восемь проверок:
результат, сохранение идентичности функции и запись метрик для обеих форм, плюс отказ
на позиционном флаге. На дореформенном коде падают четыре из восьми.
