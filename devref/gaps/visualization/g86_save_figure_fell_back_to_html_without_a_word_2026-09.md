# G86. `save_figure` отступал с PNG на HTML и не говорил почему

**Дата:** 2026-09-26
**Тип:** проглоченный отказ
**Приоритет:** 🟠 Medium — просили картинку, получили другой формат без причины
**Статус:** ✅ исправлен 2026-09-26 (запись заведена отдельным коммитом до правки)
**Найдено:** при разборе G85 — проверяли, работает ли экспорт в PNG на самом деле

---

## 1. Что происходит

`bquant.visualization.export.save_figure(fig, name, prefer="png")` у фигуры Plotly:

```python
try:
    ...
    fig.write_image(str(path), width=fig_width, height=fig_height)
    return str(path.resolve())
except Exception:
    path = out / f"{filename}.html"
    ...
    fig.write_html(str(path))
    return str(path.resolve())
```

Любое исключение экспорта ловится целиком, и функция возвращает путь к `.html`. Ни
записи в лог, ни предупреждения; причина отказа выбрасывается.

## 2. Замер

В этом окружении PNG не строится **ни на одной** из проверенных пар, и каждый раз по
своей причине:

| plotly / kaleido | что поднимает `write_image` | что вернул `save_figure(prefer="png")` |
|---|---|---|
| 6.3.0 / 1.0.0 (`uv.lock`) | `RuntimeError: Kaleido requires Google Chrome to be installed` | `.html`, молча |
| 7.1.0 / 1.0.0 | `RuntimeError: Chromium.get_cli() received invalid args` (несовместимость версий, G85) | `.html`, молча |
| 7.1.0 / 1.4.0 | `RuntimeError: Kaleido requires Google Chrome …` | `.html`, молча |

Три разные причины, одна из которых — дефект наших границ зависимостей, и снаружи все три
неотличимы. Пример из документации (`docs/api/visualization/zones.md`) сохраняет графики
этой функцией, и сьют проходит: откат делает зелёным всё, что зовёт экспорт.

## 3. Почему это дефект, хотя откат задокументирован

Докстрока честно говорит: «prefer='png' → попытка PNG (kaleido), иначе HTML (fallback)».
Сам откат — разумное поведение: график сохраняется. Дефект в том, что **причина
теряется**. Пользователь видит `.html` там, где просил `.png`, и не может узнать, чего не
хватает: Chrome, обновления `kaleido` или ещё чего-то. Правило проекта — «отказывать
громко и называть причину». Здесь нет даже тихого отказа: исключение просто
выбрасывается.

## 4. Решение (к правке)

Откат сохраняется: это задокументированное поведение, и ломать его ради громкости незачем.
Добавляется `WARNING` в лог пакета: запрошен PNG, сохранён HTML, и **текст исключения**
`write_image`. Докстрока говорит, что причина пишется в лог.

Сторож: подменить `write_image` на поднимающий исключение с узнаваемым текстом, вызвать
`save_figure(prefer="png")` и проверить три вещи: вернулся `.html`, файл существует,
в логе `WARNING` с текстом исключения. Положительный контроль: при `prefer="html"`
предупреждения нет, откатываться не с чего. Мутация: убрать запись в лог — обязано
покраснеть.

## 5. Что сознательно не входит

Окружение без Chrome — не дефект пакета, и устанавливать Chrome пакет не должен. Граница
`kaleido` — G85.


## 6. Сделано и проверено (2026-09-26)

* `bquant/visualization/export.py`: логгер модуля; при откате —
  `WARNING: PNG export of '<имя>' failed, saved as HTML instead: <тип>: <текст>`. Докстрока
  говорит, что причина пишется в лог.
* Сторож `tests/unit/test_save_figure_says_why_it_fell_back.py`, 3 проверки; мутация
  «убрать запись в лог» краснеет ровно на проверке причины, остальные две зелёные, и так и
  должно быть.
* В этом окружении настоящий вызов теперь пишет: `RuntimeError: Kaleido requires Google
  Chrome to be installed.` Раньше в логе не было ничего.
