# G85. Предупреждение об `engine` выдаёт сам plotly, а границы зависимостей допускают неработающую пару

**Дата:** 2026-09-26
**Тип:** внешнее предупреждение (не наш код) + границы зависимостей
**Приоритет:** 🟢 Low по предупреждению · 🟠 Medium по границам
**Статус:** 🟠 частично — предупреждение разобрано, правка в коде не нужна; нижняя граница
`kaleido` остаётся открытой до релизной подготовки
**Найдено:** предупреждениями полного прогона сьюта (2026-09-26)

---

## 1. Что видно

Три предупреждения на одном блоке документации, `docs/api/visualization/zones.md:425`
(прогонщик примеров `tests/integration/test_docs_examples_run.py`):

```
plotly/io/_kaleido.py:510: DeprecationWarning:
Support for the 'engine' argument is deprecated and will be removed after September 2025.
Kaleido will be the only supported engine at that time.
```

## 2. Первичный диагноз был неверен

В разговоре с владельцем я сначала сказал, что «пример в документации передаёт устаревшую
настройку `engine`». Это неправда, и запись исправляет её здесь же. Пример зовёт
`save_figure(fig, …)`, а `bquant/visualization/export.py` зовёт
`fig.write_image(path, width=…, height=…)` **без** `engine`.

Предупреждение порождает сам plotly: в 6.x `write_image` объявляет `engine="auto"` по
умолчанию и передаёт его в `to_image`, а `to_image` предупреждает на любое `engine is not
None`. Минимальное воспроизведение без BQuant:

```python
import plotly.graph_objects as go
go.Figure(go.Scatter(y=[1, 2])).write_image("x.png")   # DeprecationWarning
```

| plotly | предупреждение без аргумента `engine` |
|---|---|
| 6.3.0 (`uv.lock`) | есть |
| 6.3.1 | есть |
| 6.4.0 | есть |
| 6.5.0 | есть |
| 7.1.0 (последний на 2026-09-26) | нет — параметра `engine` больше не существует |

Со стороны BQuant снять его нечем: аргумент не наш. Глушить его фильтром значило бы
прятать чужое сообщение, а не исправлять.

## 3. Что нашлось по дороге: plotly 7 и нижняя граница kaleido

Раз предупреждение обещает удаление, проверено, что будет на plotly 7:

* 452 теста визуализации (`tests/visualization` + отобранные `tests/unit`) на plotly 7.1.0
  зелёные, предупреждений plotly нет;
* **экспорт в PNG** на plotly 7.1.0 при `kaleido` 1.0.0 (зафиксированном в `uv.lock`)
  падает внутри библиотеки: `RuntimeError: Chromium.get_cli() received invalid args:
  dict_keys(['headers'])`. Сам plotly 7.1 в своих extras требует `kaleido>=1.3.0`;
  с `kaleido` 1.4.0 остаётся только отказ окружения («нужен Chrome»).

У нас объявлено `plotly>=6.3.0` и `kaleido>=1.0.0`. Эта пара границ допускает
сочетание, на котором PNG не строится в принципе: пользователь со старым `kaleido`,
обновивший plotly, не получит от pip ни обновления, ни отказа, потому что наша граница
соблюдена. Каким путём такой отказ доходит до пользователя, описано в G86: тихой
подменой на HTML.

## 4. Решение

* **Предупреждение** — 🟢 правка не нужна. Записано, откуда оно и на каких версиях
  исчезает.
* **Граница `kaleido`** — 🟠 открыто. Правка `pyproject.toml` меняет метаданные колеса,
  то есть сдвигает выданный кандидат на релиз. По правилу, принятому 2026-09-12 для
  состава экстры `full`, она уходит в релизную подготовку: та `pyproject.toml` трогает
  всё равно (номер версии). Варианты там: поднять `kaleido>=1.3.0` или ограничить
  `plotly<7` до проверки мажорной версии целиком. Выбор за владельцем.
