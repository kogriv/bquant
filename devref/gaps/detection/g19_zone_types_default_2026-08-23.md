# G19 — дефолт `zone_types` обесточивает две стратегии детекции из пяти (2026-08-23)

**Статус:** **исправлено 2026-08-24** (этап 5 плана G20). `zone_types=None` больше не
подменяется на `['bull','bear']` и означает «не фильтровать»; `ZoneDetectionConfig.accepts()`
— единственная точка фильтрации. Замер после правки: `zone_types=None` → 44 зоны вместо 0,
заглавный Quick Start в `README.md` печатает «Found 44 zones» вместо «Found 0 zones».
**Воспроизведение:** `venv_bquant/bin/python devref/gaps/detection/g19/g19_measure.py`

---

## 1. Дефект

`bquant/analysis/zones/detection/base.py`, `ZoneDetectionConfig.__post_init__`:

```python
def __post_init__(self):
    if self.zone_types is None:
        self.zone_types = ['bull', 'bear']
```

Докстрока того же класса, восемью строками выше, обещает другое:

> `zone_types`: Типы зон для поиска (**None = все возможные для стратегии**)

Код вместо «всех возможных» подставляет словарь MACD-подобных детекторов.

Дальше каждый детектор фильтрует свой вывод через этот список:

```python
if zone_type not in config.zone_types:
    continue
```

## 2. Кого это обесточивает

| Детектор | Что выдаёт | Переживает дефолт? |
|---|---|---|
| `zero_crossing` | `bull`, `bear` | ✅ |
| `line_crossing` | `bull`, `bear` | ✅ |
| `preloaded` | `bull`, `bear` | ✅ |
| **`threshold`** | `overbought`, `neutral`, `oversold` | ❌ **пересечение пусто** |
| **`combined`** | `active`, `inactive` (дефолтный `zone_type_map`) | ❌ **пересечение пусто** |

**Две стратегии из пяти заявленных** молча возвращают пустой результат при дефолтной
конфигурации. Не ошибку — успешный пустой результат.

## 3. Замер

Данных для зон заведомо достаточно: 81 бар выше 70, 46 ниже 30 при `min_duration=2`.

```
threshold:
  zone_types=None                                 ->   0 зон
  zone_types=['overbought','oversold']            ->  18 зон
  zone_types=['overbought','neutral','oversold']  ->  44 зоны

combined (пример из собственной докстроки класса, где zone_types опущен):
  zone_types=None                                 ->   0 зон
  zone_types=['overbought','neutral']             ->  20 зон
```

## 4. Почему это трудно заметить

Детектор пишет `Detected 0 zones: OB=0, N=0, OS=0`. Ничто не сообщает, что зоны **были
найдены и затем отброшены** — счётчики обнуляются до логирования. Читается как «пороги
не подошли к этим данным», хотя данные ни при чём.

## 5. Радиус: все документированные примеры порогового детектора нерабочие

Ни один пример с `detect_zones('threshold', ...)` в репозитории не передаёт `zone_types`:

- `README.md` — **заглавный Quick Start**, он же описание пакета на PyPI (`readme = "README.md"`)
- `docs/index.rst` — титульная страница Sphinx
- `docs/api/analysis/zones.md` — 4 места
- `docs/user_guide/quick_start.md` — 2 места
- `docs/tutorials/rsi_strategy_switching.md`
- докстрока самого `CombinedRulesDetection` (второй пример)

Проверка README дословно:

```
как написано                     -> Found 0 zones
с исправленным именем колонки    -> Found 0 zones
имя колонки + zone_types         -> Found 18 zones
```

Здесь складываются **два** дефекта. `indicator_col='rsi'` не называет вычисленную колонку
(`RSI_14`); строка вообще резолвится лишь потому, что встроенный сэмпл несёт собственную
колонку `rsi` из выгрузки TradingView — это семейство G8. Затем G19 отбрасывает всё, что
нашлось. **Исправления одного имени колонки недостаточно** — нужны оба.

## 6. Предлагаемая правка и почему она безопасна

Убрать хардкод MACD-словаря: стратегия сама объявляет типы зон, которые выдаёт, и `None`
означает «не фильтровать» — как и обещает докстрока.

**Совместимость.** Изменение не может сломать работающий код:

- кто передаёт `zone_types` явно — не затронут;
- кто не передаёт и использует `zero_crossing`/`line_crossing`/`preloaded` — получит те же
  `bull`/`bear`, стратегия объявит ровно их;
- кто не передаёт и использует `threshold`/`combined` — **сегодня получает ноль зон**,
  то есть на этом поведении ничего не построено.

Иными словами, на текущем дефолте для двух стратегий не может существовать рабочего кода,
который правка сломает.

**Решено (2026-08-24): `None` = все типы, объявленные стратегией, включая `neutral`.**

Первоначальная рекомендация была обратной («стратегия объявляет *дефолтный* набор, для
`threshold` — два сигнальных»), и опиралась на довод «нейтральная зона — это скорее
отсутствие сигнала». Замер её опроверг:

| Конфигурация | Зон | Покрыто баров | Соседних пар встык |
|---|---:|---|---:|
| MACD `zero_crossing` (эталон) | 72 | 989/1000 (98.9%) | 63/71 |
| threshold **с** `neutral` | 44 | 979/1000 (97.9%) | 30/43 |
| threshold **без** `neutral` | 18 | **113/1000 (11.3%)** | **0/17** |

Без нейтральных зоны покрывают девятую часть графика и **ни одна пара соседних зон не
примыкает**. Анализ последовательностей при этом читает соседние элементы списка как
переход, то есть `overbought → oversold` означает на самом деле «перекупленность, потом
неизвестно сколько ничего, потом перепроданность». Это не приближение, а другая величина.
С нейтральными пороговый детектор мостит таймлайн так же, как MACD, и его
последовательности становятся сопоставимы с MACD-овскими.

Следствие для проектного решения: **флаг `default` из дескриптора `ZoneType` убран** —
`None` означает буквально то, что обещает докстрока, «все возможные для стратегии», и в
абстракции на одно понятие меньше. Сужение до сигнальных зон выражается явно
(`zone_types=['overbought','oversold']`) и служит хорошим примером в документации.

Остаток 2.1% и 13 непримыкающих пар к нейтральным зонам отношения не имеют — это
`min_duration`, отдельный дефект: `devref/gaps/sequence/g21_min_duration_breaks_tiling_2026-08-24.md`.

## 7. Чем закрывать от рецидива

- Тест на каждый детектор: при `zone_types=None` результат непуст на данных, где зоны
  заведомо есть. Именно этого теста и не хватало — существующие проверяют детекторы с
  явными типами.
- Тест-пин, что документированные примеры возвращают непустой результат: сегодня
  doc-parity проверяет **резолвимость** импортов и ссылок, но не то, что пример
  что-нибудь делает.

## 8. Как найдено

Не поиском. При работе над этапом A (G18) понадобился пример для документации
`library_manager.md`, показывающий, что имя колонки следует за параметрами. Пример вернул
0 зон — и вместо того, чтобы подобрать «работающие» пороги, я проверил, есть ли в данных
чему детектироваться. Оказалось, что есть, и что дело не в порогах.

Тот же урок третий раз за неделю: **прогонять то, что пишешь в документацию**. Пример,
который выглядит правдоподобно, и пример, который работает, — разные вещи.
